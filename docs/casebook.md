# 贯穿案例：每周消息简报

先从一个有限任务开始：阅读提供的材料，整理三条候选 AI 消息，去重、核对冲突，只形成草稿。如果不足三件事，说明不足；此阶段没有发送权限。

后续章节才逐步加入跨会话偏好、技能、定时任务与投递。每增加一项能力，都要解释新增状态、模块交互与代价。

## 固定的教学材料

以下产品、公告及变化全部为自编教学资料，不代表真实新闻。

| 材料 | 提供的信息 | 需要注意什么 |
| --- | --- | --- |
| 公告 A | 笔记工具甲新增纯文本导出，暂不支持图片导出 | 有明确适用边界 |
| 转述 B | 说甲工具可以完整迁移全部笔记和图片，没有给依据 | 与 A 是同一事件，且结论冲突 |
| 公告 C | 语音工具乙新增标点修正，没有公布识别准确率变化 | 不能扩大成准确率提升 |

三份材料只包含两件不同的事。任务中的“三条”不是编造第三件事的理由。它同时考察来源、重复、冲突与交付范围。

## 一次真实的受控模块观察

我们在 Python 环境中，载入 Hermes v0.22.5 固定提交的原始工具注册表和最小依赖，登记两个自编工具：读取材料、发送简报。前者可用，后者的可用性条件被设为不满足。

| 观察步骤 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 查询已登记名称 | 两个工具都存在 | 登记表示系统知道这项能力 |
| 收集模型可见的工具说明 | 只有读取材料 | 可用性条件影响本轮暴露的说明 |
| 派发读取 A 的请求 | 返回 A 的材料 | 名称可以找到对应执行者 |
| 派发未登记的名称 | 返回未知工具错误 | 没有可执行的对应项 |
| 读取请求缺少材料编号 | 返回处理器异常的错误结果 | 执行异常可以被封装为反馈 |

调用请求由固定实验驱动提供，**没有调用模型，没有发送消息，也不是完整 Hermes 任务回放**。实验只覆盖注册表的同步路径，不覆盖插件、异步执行、完整授权或模型决策质量。发送工具没有被调用，因此不能用这个结果证明所有绕过可见列表的请求都会被权限系统阻止。

第四章会用这份观察解释完整职责链。读者无需安装环境，可<a href="./observations/tool-registry.json" download>下载原始实验记录</a>查看来源摘要、请求、实际结果和范围。
