# 案例材料与观察记录

## 固定的教学材料

以下产品、公告及变化全部为自编教学资料，不代表真实新闻。

| 材料 | 提供的信息 | 需要注意什么 |
| --- | --- | --- |
| 公告 A | 笔记工具甲新增纯文本导出，暂不支持图片导出 | 有明确适用边界 |
| 转述 B | 说甲工具可以完整迁移全部笔记和图片，没有给依据 | 与 A 是同一事件，且结论冲突 |
| 公告 C | 语音工具乙新增标点修正，没有公布识别准确率变化 | 不能扩大成准确率提升 |

三份材料只包含两件不同的事。任务中的“三条”不是编造第三件事的理由。它同时考察来源、重复、冲突与交付范围。

## 一次真实的受控模块观察

我们在 Python 环境中，载入 Hermes v0.22.5 固定提交的原始工具注册表和最小依赖，登记两个自编工具：读取材料、发送简报。前者可用，后者的可用性条件被设为不满足。

| 观察步骤 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 查询已登记名称 | 两个工具都存在 | 登记表示系统知道这项能力 |
| 收集模型可见的工具说明 | 只有读取材料 | 可用性条件影响本轮暴露的说明 |
| 派发读取 A 的请求 | 返回 A 的材料 | 名称可以找到对应执行者 |
| 派发未登记的名称 | 返回未知工具错误 | 没有可执行的对应项 |
| 读取请求缺少材料编号 | 返回处理器异常的错误结果 | 执行异常可以被封装为反馈 |

调用请求由固定实验驱动提供，**没有调用模型，没有发送消息，也不是完整 Hermes 任务回放**。实验只覆盖注册表的同步路径，不覆盖插件、异步执行、完整授权或模型决策质量。发送工具没有被调用，因此不能用这个结果证明所有绕过可见列表的请求都会被权限系统阻止。

第四章会用这份观察解释完整职责链。读者无需安装环境，可<a href="./observations/tool-registry.json" download>下载原始实验记录</a>查看来源摘要、请求、实际结果和范围。

## 从循环到经验的五份教学产物

下面是固定材料的推演，不是完整模型运行日志。每份产物承接已有结果，并为下一章提供输入。

| 单元 | 新增产物 | 接着可以检查什么 |
| --- | --- | --- |
| 05 行动循环 | 每步的未知、动作、反馈与后续变化 | 重复工具调用是否减少了未知，为什么最终只交付两条 |
| 06 上下文 | 压缩前后的约束、事实、定位线索和待办 | 是否丢失图片限制，是否误把转述变成原公告 |

## 从一次任务到完整系统

10–13 继续使用同一目标，新增模型切换检查表、多入口的身份与会话对应表、独立于创建对话的定时任务卡，以及委托的任务包与返回包。三份基础材料仍由一个 Agent 处理；只有扩大为独立主题的取材工作时，才讨论可选委托。

这些卡片用于解释设计，没有创建真实定时任务、平台账号或外部发送。模型速度的比较情境没有实测数字，不能作为选型排名。

## 一次真实的受控投递队列观察

第十五章载入同一固定版本的投递队列与 SQLite 相关模块，使用临时数据库。固定驱动实际观察到：同编号入队保留首次内容；未领取的零等待项仍排队；子进程领取后退出、未写完成结果，再检查转为未知；相同编号不会重新可领取。

另外两项使用自编本地回调，分别得到完成与拒绝结果。**没有调用模型、启动真实网关或外部发送。**零等待为故障注入，不是默认配置；未覆盖死进程探测及任务/执行账本回写。不能据此声称完整 Hermes 或真实平台恢复已验证。

可<a href="./observations/delivery-queue.json" download>下载投递队列原始实验记录</a>。复现脚本、来源摘要锁与固定材料随开源仓库保存，读者无需运行代码。

## 验收与迁移

第十六章将基准、冲突、压缩、身份和投递未知等列为验收场景，尚未执行的场景明确写作预期。第十七章换成读书小组活动通知，要求自行选择必要模块，特别检查批准与草稿版本的对应关系。
