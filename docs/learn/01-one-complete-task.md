# 第一章：从一个完整任务认识 Agent

你让 AI“从三份材料里整理三条消息”。它很快交出三段文字，第一段介绍某个工具的导出功能，第二段又介绍同一更新，第三段把“修正标点”写成了“识别更准确”。格式整齐，内容却没有达到要求。

这件事暴露了三个问题：三份材料未必是三件事；转述未必支持原结论；生成一份答案，并不等于完成一个任务。本章从这里开始，认识模型、运行程序和工具怎样合作。

学完后，你应能沿着“目标—行动—反馈—交付”讲一遍过程，指出哪些步骤由人、规则或模型决定。本章留下的成果，是一份可以检查的任务要求。

## 1.1 先把要做的事说清楚

本书使用一组固定的自编资料。它们是教学材料，不代表真实产品新闻。

| 材料 | 内容 |
| --- | --- |
| 公告 A | 笔记工具甲新增纯文本导出，暂不支持图片 |
| 转述 B | 声称甲工具能完整迁移全部笔记和图片，没有附依据 |
| 公告 C | 语音工具乙新增标点修正，没有公布识别准确率变化 |

我们要的草稿需要满足四项条件：同一事件只收一次；重要说法能对应到材料；冲突和未知要说明；不足三件事时不编造第三件事。这一阶段只形成草稿，不发送给其他人。

因此，合理结果可能只有两条：一条讲甲工具的导出变化，明确图片暂不支持；另一条讲乙工具的标点修正，不扩大成准确率提升。最后说明三份材料只包含两件不同事件。

完成标准决定了哪些工作值得做。若没有这些条件，系统很容易把“凑齐三段话”当作终点。以后加入记忆、调度和协作，也必须保留这个目标，不能让新增能力改变原来要解决的问题。

## 1.2 三种做法，谁在安排下一步

第一种做法是把材料粘贴给聊天 AI。模型根据这次能读到的内容生成回答。你发现第二条重复了，再提醒它修改；缺少材料时，也由你补上。

第二种做法是安排固定工作流：程序依次读 A、B、C，按规则去重，再让模型组织文字。工作流可以有条件分支，也可以让模型参与部分判断。关键在于，主要步骤和转换条件已由程序预先规定。

第三种做法是让模型参与行动选择：它先看到任务和可用工具，提出读取材料的请求；看到 A、B 冲突后，再决定核对原公告；发现只有两件事后，停止寻找凑数的内容，并形成说明。

<TeachingFigure src="/images/ch01/three-approaches.webp" alt="聊天回答由人补充资料，固定工作流由程序安排步骤，Agent 根据行动结果调整下一步" caption="图 1-1　教学示意：比较的是行动路径如何决定。工作流也可以包含模型和分支。" />

这里把能围绕目标、利用反馈来选择后续行动的系统称为 Agent，也就是智能体。自主程度可以不同，同一个产品也可以同时包含固定流程与模型驱动的环节。有没有搜索按钮，或者名字里有没有 Agent，都不足以说明它怎样工作。

如果任务每次都只有同样三份材料、同样的规则，固定流程可能已经足够。需要 Agent 的一个理由，是执行中会遇到无法提前完全写尽的材料缺口、冲突和新约束，需要根据结果调整路线。这种灵活性也会带来选择错误和额外开销。

## 1.3 把一句“我去查”拆成三个责任

模型是根据本轮输入产生响应的部分。响应可能是答复，也可能是“读取 A”这样的调用请求。模型发出请求时，页面或文件还没有因此自动被读到。

运行程序负责把目标、历史和可用能力组织起来，请求模型，承接它提出的行动，再将实际结果送进后续判断。Hermes 组织的正是这些工作，以及它们所需的状态和限制。

工具负责接触环境。读取工具可以取得材料；发送工具可以把信息交给外部服务。实际能访问什么，取决于工具、配置和执行环境。我们当前只需要读取，不需要发送。

| 责任 | 简报中的动作 | 观察时应该寻找什么 |
| --- | --- | --- |
| 模型 | 提出读 A，判断 B 与 A 冲突 | 返回的行动请求或答复 |
| 运行程序 | 组织输入、执行调用、处理反馈 | 请求与结果是否对应，下一轮实际带入了什么 |
| 工具 | 读取 A，返回原文 | 真正取得的内容或错误 |

这种分工让我们有办法判断问题发生在哪里。读到了旧材料，是取材环节的问题；取到了新材料却没放进后续输入，是反馈组织的问题；材料已经在输入中，模型仍扩大结论，则要检查解释与判断。不能把所有失败都归结为“模型不够聪明”。

## 1.4 跟一次任务走过反馈回路

下面是教学示意，并非模型实测日志：

1. 用户提出目标、完成标准和只形成草稿的范围。
2. 运行程序把目标与读取能力交给模型。
3. 模型提出读取 A、B、C 的行动，工具返回相应材料。
4. 后续判断发现 A、B 是同一事件，而且图片说法冲突。
5. 系统围绕冲突继续核对，保留能够被材料支持的范围。
6. 形成两条草稿，解释为什么没有第三条，结束本次任务。

<TeachingFigure src="/images/ch01/action-loop.webp" alt="整理当前信息后决定下一步，执行工具并接收真实结果，反馈进入后续判断；信息足够时交付" caption="图 1-2　教学示意：回路让新结果有机会改变行动。图中的每次绕行，都需要有具体理由。" />

这个回路叫行动循环。反馈不只是成功的正文，也包括“材料为空”“读取失败”“内容矛盾”。下一步是否合理，要看它准备解决哪个未知，而不能只看动作是否更多。

系统仍可能判断错：它可能相信 B 的夸大说法，重复读取同一份材料，或者提前结束。Agent 提供了调整行动的机制，可靠程度则需要看实际设计、运行条件和验证。

## 1.5 我们将逐步增加什么

现在的助手只处理当前资料。材料增加后，需要整理本轮输入；重新开始对话后，需要区分旧会话和精选记忆；反复完成相似任务后，可以保存方法；要下周自动运行，才引入调度与投递。

每一项机制都应回应一个已经出现的困难。先把最小系统理解清楚，后续才有依据判断哪些能力必要，哪些会增加不值得的复杂度。

本章的案例产物是任务卡：**材料范围、去重与核实要求、允许的行动、交付形式、不足时怎样说明。** 下一章会把这张卡放进 Hermes 的系统地图。

## 本章要点

- 一份任务需要明确的完成标准，生成文字只是过程中的一种能力。
- 模型提出判断和行动，运行程序组织过程，工具实际接触环境。
- Agent 把一部分后续行动选择交给模型，并让真实结果进入反馈回路。
- 灵活调整有价值，也会引入错误与成本；是否需要它，要看任务条件。

## 理解题

::: details 1. 用户说“必须写三条”，材料却只有两件事，应该怎样处理？
先结合任务的核实要求判断。“三条”不能使不存在的事件变成事实。应交付能支持的两条并说明不足；若用户允许继续取材，可以寻找第三件有依据的事。继续检索和编造第三条是不同动作。
:::

::: details 2. 每天按相同规则读三份材料，再让模型总结，是否必须改成 Agent？
不必。若流程确定，固定工作流可能更容易检查和控制。只有出现需要根据材料缺口、冲突等调整行动的部分，才有理由让模型参与后续选择。应解释收益是否超过新增复杂度。
:::

::: details 3. 最终草稿采用了 B 的图片说法，怎样沿过程缩小问题范围？
先确认读取到了哪些内容，再看 A、B 是否都进入后续模型输入，最后看生成结论时有没有保留冲突和条件。只有知道实际输入和结果，才能区分取材、反馈组织与模型判断的问题。
:::
