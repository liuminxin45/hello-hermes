# 术语表

定义按本书讨论的 LLM Agent 工程语境使用。遇到不同项目的同名概念时，要继续核对它的实际责任与边界。

| 术语 | 本书中的含义 |
| --- | --- |
| Agent（智能体） | 根据目标和当前结果决定后续行动，通过运行程序与工具接触环境的系统 |
| Workflow（工作流） | 主要由程序预先定义步骤和转移条件的流程；步骤中可以使用模型 |
| Runtime / Harness（运行程序／运行支撑） | 组织模型调用、工具执行、历史、限制和恢复的软件；不是模型权重 |
| Agent Loop（行动循环） | 准备信息、请求模型、执行行动、接收反馈并继续或结束的反复过程 |
| Tool Calling（工具调用） | 模型输出结构化调用意图，由程序检查并执行，再将结果带回模型 |
| Registry（注册表） | 保存工具名称、输入约定、执行者与相关条件，供发现与派发使用 |
| Schema（输入结构约定） | 描述参数的字段、类型等要求；存在约定不表示所有业务条件已自动校验 |
| Handler（处理器） | 接到派发后的实际执行逻辑；它可能完成检查、调用外部服务并封装结果 |
| MCP | Model Context Protocol，模型上下文协议；为工具等能力提供标准连接方式 |
| Context（上下文） | 当前一次模型请求能读到的信息，不等于硬盘上保存的全部资料 |
| Token | 模型处理文本等输入输出的计量单位；不与汉字或单词一一对应 |
| Compaction（上下文压缩） | 为控制上下文体积而精简历史、生成摘要等；摘要可能丢失细节 |
| Prompt Cache（提示词缓存） | 服务端复用符合条件的输入前缀计算；具体行为依赖提供方 |
| Memory（持久记忆） | 为后续会话保留的精选事实与偏好；不同于当前完整上下文 |
| Retrieval（检索） | 按当前需要找回相关资料；能找到不等于已经正确理解 |
| Skill（技能） | 按需加载的任务方法与资源，可能包含说明、脚本和参考材料 |
| Curator（技能维护器） | Hermes 中对技能等经验材料进行维护的机制；有范围、触发与修改约束 |
| Provider（模型提供方） | 提供模型访问的服务方；同一模型可能有不同服务入口 |
| Adapter（适配器） | 在共同运行逻辑与具体服务之间转换请求、响应和事件约定 |
| Session（会话） | 一条有身份、历史和生命周期的对话；应用重启不必然结束它 |
| Run（一次运行） | 围绕一项请求推进的执行过程，可包含多轮模型与工具往返 |
| Gateway（消息网关） | 连接外部消息入口，处理消息适配、路由和会话等运行事务 |
| Profile（配置档） | Hermes 中组织配置、身份与状态目录的单位；不等同于操作系统安全隔离 |
| Delegation（委托） | 将限定任务交给子 Agent，并取回结果；不是无成本地复制能力 |
| Queue（队列） | 记录尚待处理与处理中事项的归属、顺序和状态，不代表事项已经完成 |
| Idempotency（幂等） | 在规定范围内重复同一操作，不重复改变既有结果；依赖稳定身份与具体处理规则 |
| Unknown（结果未知） | 已有动作可能发生，但证据不足以确认结果；不能自动当作未执行或成功 |
| Trace（任务轨迹） | 一组可观察的输入、响应、动作与状态事件，不是模型隐藏思考的完整记录 |
| Sandbox（沙箱） | 限制程序接触资源的执行环境；能隔离什么取决于具体配置 |
| Prompt Injection（提示注入） | 不可信材料试图被系统当作有权决定行动的指令 |
| Verification（结果核实） | 用独立于生成过程的证据检查交付是否满足要求 |

概念分别在对应章节展开。某个术语出现在项目宣传中，不代表其实现具有这里描述的所有性质。
