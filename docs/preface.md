# 序言：沿着一个任务，理解 Agent

把“查找这周值得关注的 Agent 变化，写成一份带来源的简报”交给 AI，它可能很快给出一篇流畅的文章。但你仍然需要问：资料真的查过吗？版本对吗？找不到证据时，它为什么还继续往下写？

这些问题指向的，正是本书要解释的东西：**一个 Agent 怎样把模型的判断接到真实行动上，又怎样约束和验证这些行动。** 我们选择 Hermes 作为可观察的样本，逐步拆开循环、工具、上下文、记忆、技能和协作，也对照 OpenClaw 看不同选择的代价。

## 你需要知道什么

知道大模型能根据提示词生成回答，听说过 API，就可以开始。首次出现的必要术语会在正文解释，也能在[术语表](./glossary.md)查到。

正文不要求安装 Hermes 或编写 Python。源码阅读放在每章末尾，想继续追问“依据在哪里”时再打开。书中的运行过程如果没有真实日志支撑，都会标为教学示意。

## 同一个案例怎样贯穿十四章

先从一份技术简报开始：模型需要什么资料，工具能返回什么，失败后怎么调整。然后让任务跨越更多轮对话：哪些信息要留下，哪些经验可以写成技能。再把它变成长期任务：更换模型、定时执行、委托其他 Agent，最后检查权限和交付证据。

这样安排，是为了让每个新概念都回应一个已经出现的问题。你不必先记住一串模块名，再猜它们为什么存在。

## 怎样阅读与核对

第一次建议顺序读。每章的“本章要点”用于回顾，理解题用于检查自己是否能把机制用到一个稍有变化的情境中；答案可以展开查看。

章节上方标注对应版本和核对日期。它表示我们对照过该版本的资料与实现，不表示在所有平台、模型和环境上做过完整运行测试。想检查具体依据，可看章末链接及[版本与来源](./sources.md)。

这是社区学习手册，与 Hermes、Nous Research、OpenClaw 和 Datawhale 无隶属关系。讲解节奏参考 Hello Agents，内容与配图独立编写；参考资料保留原始链接。

## 怎样跟上变化

维护者在 Codex 中打开本仓库，说“跟上官方最新，更新手册”，即可调用随仓库提供的维护技能。它先收集变化，再判断是否影响已发布的讲解；有实质修订时完成正文、图解和校验，交付维护 PR。审核合并后发布。

一次更新的目标，是修正读者需要理解的机制。版本号本身不会成为必须改写一章的理由。
