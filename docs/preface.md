# 序言：从一次任务，理解一个系统

你把三份材料交给 AI，让它整理三条消息。它很快写出一份完整简报。但三份材料里，有两份说的是同一件事，另一份还夸大了原公告。写出三段话，并没有解决这个任务。

如果让它自己取材料、核对冲突、记住偏好，下周再做一遍，系统需要增加什么？哪些决定可以交给模型，哪些事要由程序落实？资料和状态又应该保存在哪里？

本书以 Hermes 为实例，沿着这些问题理解一个 Agent（智能体）系统。你将先看懂一次行动，再逐步理解工具、上下文、会话、记忆、技能、调度和协作，最后学会分析这些模块为什么这样配合。

## 从哪里开始，需要学到哪里

会使用聊天 AI 就可以开始。你不需要先理解 API，也不需要安装 Hermes、编写代码或阅读 Python。必要术语会在使用时解释；图解、输入输出和状态对照承担主要讲解工作。

本书的终点也不仅是记住模块名称。学完后，你应当能够：

- 沿着一次任务说明谁做判断、谁执行、谁保存结果。
- 推演条件改变后，系统下一步会怎样处理。
- 比较两个设计办法，解释收益、代价与适用边界。
- 为一个新需求画出合理架构，包括说明哪些能力暂时不需要。

普通读者可以先掌握每章的主流程，再读设计追问和练习。深入理解靠逐层推导，不要求靠记住更多文件名。

## 同一个助手，逐步增加能力

贯穿任务是“每周整理三条我关心的 AI 消息”：先核对原始材料、去重并形成草稿，后来再增加偏好、方法复用和定时投递。

开始时，所有材料由用户提供。随后让工具取得材料，让模型根据反馈选择下一步；材料过多时整理上下文；对话结束后区分会话、记忆和技能；最后才讨论多入口、后台执行、委托、权限与恢复。

每章都接住上一章的成果，并说明新增机制解决了哪个困难。最初的完成标准，会逐渐变成输入包、工具职责链、状态图、记忆和技能材料，最后汇成一份可解释的系统方案。

基础案例使用自编的固定材料，不代表真实产品新闻。这让我们能反复讨论同一处冲突，而不被搜索结果变化打断。实际运行观察会单独说明环境与范围，详见[贯穿案例](./casebook.md)。

## 读每章时，带着三个问题

第一，**这项机制在系统里的位置在哪里？** 第二章建立系统责任图与任务时序图，后文会不断回到它们。

第二，**为什么需要这样设计？** 先理解最简单的办法会遇到什么困难，再看 Hermes 的选择及其代价。教学分层只是理解视图，不表示官方代码严格分成同样的几层。

第三，**我能否用已有材料推演一个变化？** 理解题会改变输入、状态或约束。你需要说明下一步和理由，而不只回答“对”或“错”。

正文不设置源码跳转与引用。实现和版本仍由维护者在内部核对；读者可以在页面内完成机制理解，不必跳到另一个代码世界。

## 看清证据的性质

书中区分教学示意、固定版本实现确认、受控模块实验和完整模型运行。一个注册表实验能说明那条执行路径的结果，不能证明模型会选对工具；站点构建成功也不能证明 Hermes 的任务效果。

各单元的完成状态见[学习路线](./roadmap.md)，完成核对后分批上线。导航和搜索只包含已发布内容。[旧版十四章](./legacy.md)继续保留供对照，不与新版混作同一套课程。

Hermes 与 OpenClaw 的比较会围绕相同问题展开，讨论具体选择，不凭功能数量给总分。最终的综合项目要求你将这些思想用于新需求。
