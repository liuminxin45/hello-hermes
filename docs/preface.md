# 序言：为什么今天还要理解 Agent

我们对 AI 的期待，正在从回答一个问题，延伸到完成一项工作。请 AI 解释一份材料时，我们关心它能否给出恰当的答复；整理持续更新的资料、修改一个项目、把结果交给指定的人，则还涉及取材、执行、核对和后续处理。任务跨过多个步骤，新的问题就出现了：下一步由谁决定，结果保存在哪里，出错以后怎样继续？

大语言模型（LLM）提供了理解语言和生成响应的能力。基于它的 Agent（智能体）系统，则把模型与工具、运行程序和保存的信息组织起来，让助手能够根据执行结果继续行动。它连接了语言中的目标与计算机中的实际操作。

## 从对话走向行动

这条路线已经留下了一些清晰的节点。2022 年的 ReAct 研究把判断与行动交替组织；2023 年的 AutoGen 探索多个 Agent 的协作编排；2024 年公开测试的 Computer use，让模型通过观察屏幕、点击和输入操作界面；2025 年，Claude Code 以研究预览的形式开放，面向软件开发任务。

这些变化扩展了 AI 参与工作的方式。对个人而言，资料整理、跨应用操作和长期维护的任务，有了减少重复劳动的机会；对组织而言，模型也可以参与资料核对、开发协作等工作流程。与此同时，行动会带来实际后果：一份草稿可以修改，已发送的消息、覆盖的文件和泄露的信息，则需要追踪和处理实际后果。Agent 的价值与难题，都在这些具体环节里。

## AI 能写代码之后

AI 编程工具能够分担代码生成工作，但生成了一套能运行的程序，还不足以判断它是否解决了真正的问题。任务怎样拆分，哪些信息值得保留，哪些操作必须由人确认，结果又该怎样验收，都需要有依据的设计。读懂、验证和修正代码仍然重要，系统的责任和边界也同样重要。

未来，更强的模型可能直接生成更多 Agent 代码，也可能把今天的一部分编排能力吸收到模型或平台中。实现方式会变化，使用者和设计者仍要判断：给它什么目标、什么资料、多少权限，以及凭什么相信任务已经完成。理解优秀系统的设计，可以帮助我们提出更清楚的要求，审查 AI 给出的方案，在出现偏差时知道从哪里查起。

## 沿着 Hermes，理解设计的来由

Hermes 提供了一个真实的工程实例。模型调用、工具执行、会话、记忆、技能与定时任务，在同一个系统中相互配合。沿着这些机制，我们可以看到，一次请求怎样变成行动，偏好怎样延续到后续任务，经验怎样整理为可复用的方法，以及失败和权限边界怎样影响系统的行为。

本书用“每周搜集三条我关心的 AI 消息”贯穿讲解。我们从能够处理给定材料的最小系统出发，每遇到一个实际困难，再补上必要的能力。工具、记忆或调度都从它要解决的问题引出，随后解释职责、交互和代价。通过图解和推演，你会逐步形成一个保留核心机制的“简化版 Hermes”设计，再把这些理解迁移到自己的需求中。

阅读本书不需要先安装 Hermes、编写代码或阅读 Python。必要术语会随问题引入，机制会通过案例和图解展开。我们从[第一章：从一个完整任务认识 Agent](./learn/01-one-complete-task.md)开始。
