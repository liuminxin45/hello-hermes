# Hermes Agent 工厂实习馆

2026-10-28。将网站主入口从连续图文阅读改为可操作的工厂实习。原十八章保留为图文资料，原 URL 继续提供。不是官方版本同步，也不把教学参数记为 Hermes 核对结果。

## 定位与旅程

面向会使用聊天 AI、没有架构基础的读者；以一笔欢迎礼盒订单理解输入、判断、调度、工具、上下文、记录、复用、检查和权限。程序员可以从同一任务观察状态归属、调用边界与恢复代价。

厂外下单 → 导师接待 → 八站参观 → 成品验收 → 实景参观报告 → 十题考核 → 纪念证明 → 感谢导师并离场。默认自动讲解，可随时暂停、手动前进、提问、回访、环顾和拍照。预估完整体验 20–25 分钟，实际按个人阅读与操作节奏决定，不以等待计时验收。

导师为橙色引导服的三维人物小赫，生产工人为蓝色。文字对话，无配音或模型服务依赖。角色定位和说话内容分别保存在场景与课程数据中。

## 两种流动

- 实体：货架原料 → 工人领取 → 印卡装盒 → 质检 → 验收台。
- 信息：订单 → 方案与调度 → 库存查询 → 工具反馈 → 后续安排与记录。

方案室比喻模型服务的作用，本馆用确定性规则规划。调度台接住请求、派工、保存结果；工人执行具体操作。模型请求不等于工具已执行，工具成功不等于目标满足。

## 八站与脚本

1. 方案室与调度台：目标如何变成下一步，请求和执行分别发生。
2. 原料仓库：同款包装不足时，返回实际情况并在原目标内换方案。
3. 调度室工作台：本轮可见输入与长订单压缩实验。
4. 会话档案室：完整记录与当前输入分开，查看本单实际事件。
5. 偏好柜与手册架：技能提供做法，偏好须自愿保存；新明确要求优先。
6. 装配车间：真实扣减教学库存，按输入生成工件与欢迎卡。
7. 质检与返工口：按订单检查，只补做缺少的卡片，不重复扣料。
8. 出厂验收台：展示产物与费用，确认验收不触发发货。

每站有三段主讲和点选子问题。完整导师台词、回答与题库由 `docs/public/factory/content.mjs` 维护，页面、报告和考核使用同一份知识材料。

## 上下文如何合理出现

简单礼盒订单不必压缩。导师从楼下生产车间带到楼上调度室，观察工作台上的订单、库存和沟通资料。压缩通过独立的长订单实验展示，明确是同一订单多轮沟通的教学分支，不污染基础订单的生产记录。

示例容量 100 信息格，输出预留 20 格，整理线 70 格。常驻规则 10、Head 10、中部 40、Tail 15，总计 75；将中部改成 10 格工作摘要后总计 45。Head、Tail 本次原文保留，Tail 以后会滚动。信息格不等于真实 token，比例不是 Hermes 默认值。

对照实验“包装已安排”展示摘要丢失材料、依据、约束和未完成事项的风险。没有模型摘要调用，不展示推测的隐藏思考。原始记录与当前摘要分别保留。

## 报告与考核

报告包含参观编号、昵称、实际日期与在馆时长、订单要求、实际产物与费用、完成站点、实景照片、实际点选的问题与答案、观察总结、独立实验、操作记录、完整测试成绩与结业状态。

照片来自当时的 Three.js 画面，绑定站点、事件位置、时间和说明。自动照片在镜头到达后捕获；支持手动拍照，最多 16 张。没有捕获就标记缺失，不用预制宣传图补齐。

导出自包含 HTML，图片内嵌；提供打印版以保存 PDF。测试十题，每题十分，八站完成且最高完整成绩达到 80 分可领取 PNG 纪念证明。可重试、回访、查解析；不要求必须提问或下载。未通过不限制退出。

## 数据与发布

订单、库存、工件、工具事件、上下文实验、参观、相册和考核分开管理。动作幂等：重看与恢复不重复领料。浏览器本机 IndexedDB 保存当前与历次实习；不收集远程分析，不使用模型密钥。

Three.js 0.180.0 静态资源本地打包。现有 VitePress 继续构建图文资料，再将工厂入口设为站点首页。GitHub Actions 校验后发布 GitHub Pages；公共产物继续检查本地批注和私有数据隔离。

首版没有真实 Hermes 运行、购买、物流、头显 WebXR、定时任务或多 Agent 展馆。教学模拟、浏览器检查与官方实现核对分别记录。
