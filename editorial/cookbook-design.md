# hello-hermes 体验式 Cookbook：定位与设计提案

历史提案：此文件保留最初的简报工厂原型设计。当前正式实习馆采用实体欢迎礼盒与独立长订单实验，详见 `factory-blueprint.md`。

日期：2026-10-28。状态：方向提案，已制作一个独立的三维交互原型；尚未替换当前十八章课程。

## 定位

**一座可以亲手操作的 Agent 系统展馆：以 Hermes 为实例，跟着任务走进系统，观察信息怎样流转，再通过改变条件理解设计取舍。**

读者会用聊天 AI 就能开始。不需要安装 Hermes、配置 API 或阅读 Python。学习的终点是能解释系统怎样配合、为什么需要某个机制，以及换一种办法会付出什么代价。

普通读者先得到直观理解：为什么 AI 还需要工具，为什么结果要回来，为什么记住过不等于这次看得到。程序员在同一次体验中继续检查输入输出、状态归属、失败传播与替代设计。核心因果对所有读者展开；更细的工程讨论按需打开。

这里的 cookbook 以“能完成的体验”组织。每个单元从一个具体任务进入，读者亲手改变一个条件，观察结果，再带走一个能够迁移的认识。章节仍可承担解释与回顾，但不再让连续阅读成为体验的前置条件。

## 为什么尝试三维工厂

工厂适合表现交接与重复劳动：人只在入口交代一次目标，材料在不同职责之间流转，结果回来后继续处理。它尤其适合展示 Agent 的循环——工具执行后，任务通常还需要带着新信息继续判断。

三维的收益来自稳定的空间关系。读者可以拉远看到系统，走近一个工作台，再沿同一份材料回到全景。传送带让“信息已经送到哪里”可见，档案柜与工作台的区别让“存下了”与“这轮看到了”可见。

代价同样明确：视角会遮挡，空间会增加认路负担，低性能设备可能吃力。因而默认提供能看见内部的全景、按站点参观、暂停和逐步回放。自由穿行是可选能力；关键状态同时有文字记录。不能让读者先学会控制游戏，才能理解 Agent。

不要一次把整个系统铺成一座信息过载的大城。先让一条任务路径成立，再逐步开放新的车间。巨大的 HTML 可以是一体的学习空间，内部内容仍应按区块加载和维护。

## 视觉语言必须有含义

| 展馆里的东西 | 表示什么 | 需要避免的误解 |
| --- | --- | --- |
| 建筑与工作台 | 某项职责及其输入输出 | 不是源码目录、独立进程或实际部署拓扑 |
| 传送带与移动材料卡 | 一次明确的信息交接，卡片说明载荷 | 不是所有数据都在无限循环；路程不代表耗时 |
| 调度中心 | 程序接收响应、调工具并推进任务 | 不能把模型请求画成工具已经执行 |
| 独立的模型平台 | 模型服务接收输入、返回响应的边界 | 不可把动画当作隐藏思考或神经网络内部过程 |
| 上下文工作台 | 本轮实际提供给模型的材料 | 不等于全部历史与所有持久资料 |
| 会话档案 | 当前任务中保存的记录 | 存进档案不表示已经装入本轮输入 |
| 记忆与技能库 | 按需要读取的长期资料和可复用做法 | 不表示每轮读取全部资料，更不是更新模型权重 |
| 交付出口 | 已经交到人手里的结果与剩余缺口 | 形成草稿不等于已经发布，也不等于内容必然正确 |

模型返回的工具请求同时携带控制意图；材料卡的文字要说明这一点。原型暂不额外叠加一套容易混淆的控制线。后续若提供“只看控制关系”视图，应与现有职责图、任务时序图使用相同术语。

本原型是用户明确提出的 Three.js 空间交互实验。现有静态教材图的制作与验收规范继续适用于正文配图；这里的原生几何、相机与状态动画单独维护。

## 学习怎样发生

一次体验采用四个动作：**先看一次 → 停在交接处 → 改一个条件 → 解释差异。**

开始只给任务与开始按钮，不把整张架构名词表放在读者面前。运行中一次强调一个观察点。点击建筑可看到职责、输入和输出，再展开机制与取舍。运行记录保留已展示的步骤，帮助读者回看。选择观察点时暂停，避免一边读解释，一边错过后续变化。

每个单元应有一个可以观察的反事实。例如工具读取失败后，系统可以返回错误，却不能声称完成消息核对。比较的重点是结果和状态有什么变化，不是让两条动画跑出预设的输赢。

最终验证理解时给一个变化了的需求：如果只总结用户已经粘贴的材料，哪些取材步骤可以省略？如果要定时发送，现有工厂又缺什么？读者应能从已见过的交接关系解释答案。

## 建议的体验单元

| 体验 | 读者亲手改变什么 | 应带走的认识 |
| --- | --- | --- |
| 1. 把一项任务交出去 | 逐步运行与自动运行；后续再加入人手搬运对照 | 自动化接走重复交接，人仍需要定义目标与边界 |
| 2. 工具执行后，为什么还要回来 | 正常取材 / 读取失败 | 模型响应、程序调度、工具结果分别发生；成功不自动传递到任务 |
| 3. 模型这次究竟看到了什么 | 保留或移除一份关键材料 | 当前输入决定可用证据；档案里有不等于本轮可见 |
| 4. 任务变长以后 | 输入空间、保留策略 | 压缩或筛选节省空间，也可能丢失关键条件 |
| 5. 关掉再回来 | 有无保存；从哪个状态继续 | 继续任务依赖可恢复状态，不能靠界面看似还在 |
| 6. 下次还要重新交代吗 | 长期偏好与技能按需读取 | 历史、记忆、技能的作用不同；复用带来便利也需要适用范围 |
| 7. 换一个入口 | 聊天入口 / 定时触发 | 入口可以不同；身份、上下文与权限不能随意共用 |
| 8. 多开一个帮手 | 单任务 / 有边界的委托 | 分工可以并行，也增加交接、协调和汇总成本 |
| 9. 工厂遇到故障 | 中断点、重试与有副作用的操作 | 重新运行与安全恢复不同，重复执行可能产生重复影响 |
| 10. 为自己的任务改造工厂 | 为需求选机制并说明省略理由 | 能迁移设计判断，而不是背出模块名字 |

这是体验结构草案，不代表以上交互已经全部实现，也不直接把当前十八章一对一改名。下一步用前两个单元验证学习收益，再根据覆盖关系调整现有课程。

## 已做的第一版

位置：`prototypes/hermes-factory/`。启动：`node prototypes/hermes-factory/serve.mjs`，默认 `http://127.0.0.1:4397/`。

已实现：八个可点选的职责空间、旋转缩放、按站点飞行、车间内低视角移动、自动/暂停/逐步/定位回放、十二次交接、固定材料与记录、正常/取材失败两种情境、深浅主题、触屏控制和减少动态效果偏好。

案例复用 `examples/news-brief/materials.json` 的虚构 A/B/C 材料：A、B 重复且说法冲突，C 为第二件事件，因此交付两条消息并说明不足。原型新增“读取材料”和已存简报做法的教学设定，用于显示工具与资料读取的职责，不声称它们是实测配置。

本轮刻意采用确定性回放，让读者能够重复比较同一个故障。**没有连接真实 Hermes、模型 API 或外部工具，也没有真实搜索、发布或训练。**运行时不依赖外部 CDN。Three.js 固定为 0.180.0，并保留 MIT 许可。

仍待实现：人力搬运与自动流转的工作量对照、上下文容量实验、状态检查点、多任务协作、真实轨迹适配、选定版本的逐项语义验收。本轮没有更新官方实现核对日期。

## 从原型走向正式 Cookbook

先邀请几位无架构背景读者完成一次参观，看他们能否解释“谁执行工具”“为什么结果回来”“为什么只交付两条”。如果必须依靠作者讲解才能答出，就先改交接和反馈，不急着扩大工厂。

随后增加人力与自动流转的并排比较。使用相同材料、相同完成标准，明确记录需要人发起的交接次数；这些是教学操作计数，不能包装成未经测量的生产力提升比例。

再将展馆与现有书页连接：点击某个职责可以进入对应解释；读完一章可以回到同一观察点。保持一个场景和一套状态语义，避免每章新建一座不同配色、不同术语的工厂。

接入真实轨迹时，数据适配层只接收实际可观测的请求、工具参数摘要、结果状态、保存动作和时间；隐私内容需脱敏。每段轨迹保留版本、来源和采集条件，明确区分真实事件与教学补充。不能从日志空白处猜测模型内部过程。

正式交付前还需建立事实核对表：每个真实机制对应固定 Hermes 版本与内部证据；未覆盖的部署差异和省略项记录在内。交互测试、架构核对和学习效果测试分别验收，三维渲染成功不能代替另外两项。

## 参考教学方向

- [掘金文章](https://juejin.cn/post/7641474594384330752)：以源码解释记忆、上下文压缩、MCP 等机制。可用于了解已有教程选题，具体实现仍须按本项目固定版本核实。
- [Hermes Agent Anatomy](https://github.com/anneheartrecord/hermes-agent-anatomy)：仓库说明采用源码模块分析与技术图解。网页为动态加载，本次没有完成其渲染界面的视觉比较。
- [Hermes Teardown](https://github.com/leezythu/hermes-teardown)：仓库说明从最小循环逐层加入能力，以缺少某项能力时的问题解释设计。这里借鉴问题驱动的顺序，让读者直接操作条件并观察后果。其动态网站界面同样未作完整视觉评测。

这些教程为读者提供实现层面的继续阅读。本 Cookbook 的首要价值是让系统关系与设计后果可以观察、操作和比较。
