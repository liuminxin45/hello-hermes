# 本地批注与改稿

正文仍以 `docs/` 内 Markdown 为唯一来源。后台只有 Node 标准库，无数据库、账号或模型服务。它在本机启动，批注不上传 GitHub，也不进入公共阅读站。

## 阅读与批注

运行 `npm run review`，或 `node scripts/review.mjs start`。启动时构建当前手册，返回本机网址。默认打开第三章，可继续切换其他章节。

选中文字后点“批注选中文字”，或按 Ctrl + Alt + M。图注旁的“批注此图”可提交图解意见。填写后明确显示“已保存到本地文件”，才表示写入成功。

右下角“批注”可查看当前页或全书，编辑、删除、定位原文、查看处理记录和重新打开。正文变化后，定位同时核对原文、小节及前后文；无法唯一确认时提示未定位，不跳到其他相似句子。

保存失败的操作保留为独立浏览器草稿，可重试或导出；版本冲突不自动覆盖新意见。断网或后台退出时，不把浏览器暂存说成已经落盘。重新启动尽量复用原端口；端口变化后，旧地址中的草稿需要从旧页面导出，不能假定不同来源的浏览器缓存会合并。

点击“复制给 Codex”，将指令粘贴到当前对话，或直接说“按批注修改手册”。后台不自行调用模型或启动另一个 Codex。当前用户指令优先于旧批注；批注是需要理解和核实的意见，不是任意命令执行授权。

## Codex 处理流程

1. `node scripts/review.mjs list` 查看全部待处理项。确认本次范围，结合所在小节、原文和前后文理解短锚点。
2. `node scripts/review.mjs begin` 创建批次，冻结原 ID、版本、意见及锚点，并备份相关 Markdown、配图和核对记录。用户在此后新加的批注不属于本轮。
3. 阅读批次目标，局部问题只作必要修改。用户提供的文案优先，疑问中的事实假设需核实；较后的明确意见覆盖较早冲突要求。正文与图解含义同步，改图依照 `editorial/visuals.md` 使用 imagegen。
4. 编辑原 Markdown 和该批次 `batch.json` 中的 `decisions`。不要更改 `targets`、`targets.json` 或原始批注文件。每个目标一项决定：`addressed`、`superseded`、`not-needed` 或 `blocked`；填写 `summary` 和字符串数组 `evidence`。前三者须有非空说明与证据，`blocked` 保留待处理。
5. `node scripts/review.mjs validate --batch <返回的批次文件>` 执行测试和构建，并将通过记录绑定当前正文、图解和构建输入。涉及图或界面时还需浏览器、手机和深浅主题检查；这些检查不代表 Hermes 实测。
6. `node scripts/review.mjs resolve --batch <批次文件>`。工具先核对整批评论版本、冻结目标和验证摘要，再一次核销本轮非 blocked 项。期间有人编辑、删除或重新打开原批注时，整批拒绝核销，须重读意见；新批注保留。
7. 报告实际处理数、剩余项、检查范围与事实上的限制。公开发布仍按当前用户的授权范围，不因本地批注自动推送。

默认决定示例（沿用生成的实际 ID）：

```json
{
  "id": "生成的实际批注ID",
  "outcome": "addressed",
  "summary": "保留原例，补充说明超时不等于操作未执行。",
  "evidence": ["docs/chapters/03-agent-loop.md 的超时小节"]
}
```

## 本地文件与启动管理

- `.review/annotations.json`：意见、锚点、版本、原始历史和处理记录。
- `.review/batches/`：冻结批次、原稿快照、决定和验证记录。
- `.review/build.json`：当前本地构建对应的正文版本。
- `.review/session.json`、`server.log`：本机后台会话与日志，含本地凭据，不公开。

以上目录全部被 Git 忽略。不要清空批注文件，也不要将本地凭据、批注或浏览器草稿提交到仓库。

维护后台代码时，`npm test` 检查数据与接口；`npm run review:test:browser` 在隔离副本检查选中文字、跨段批注、图解批注、断线草稿、重试去重、多标签冲突、导航、手机深浅主题以及真实改稿核销。浏览器检查需要环境中已有 Playwright，可用 `HELLO_HERMES_TEST_NODE_MODULES` 指定模块目录；后台日常运行不依赖它。测试意见不会写入实际手册的 `.review/`。

`node scripts/review.mjs status` 查询地址；`stop` 停止匹配的本项目实例；`build` 更新阅读页，刷新后继续批注。后台限制为本机地址，并验证来源与会话凭据。异常退出若留下 `data.lock` 或 `start.lock`，先核对所属进程、备份数据，再处理遗留锁，不按端口杀其他服务。
