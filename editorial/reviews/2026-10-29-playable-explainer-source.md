# Hello Hermes：从“工厂参观”转向“可操作的 Agent 运行过程”

日期：2026-10-29  
用途：产品方向重设与交互原型约束，可供 Codex 实施前阅读。  
核对基线：hello-hermes 仓库 `d68cf9e248cae8d23b0f78373fcdafaf8d6d9d92`。

## 0. 结论与范围

推荐定位：**Hello Hermes｜看见 Agent 如何工作**。

不再继续加固“工厂实习馆”的世界观。保留立体感、资料流转、可选深入、学习记录与报告；撤掉建筑漫游、车间巡礼、工人和导师角色、默认数字章节导航，以及把每个概念都做成一台机器的要求。

新的核心是一张稳定的、可操作的工作过程示意图：用户提出目标；当前资料进入模型；模型产生回答或工具调用请求；运行时执行工具；返回结果改变当前资料与后续行动。局部展开上下文整理；随后新建会话，观察 Hermes 的记忆、技能与历史如何分别参与。

**主角是信息、请求、结果和它们的变化，不是设备。**

本轮已读取新版首页源码与参考项目的一手页面或 README。浏览器连接不可用，公开首页抓取也未成功；没有声称实际点击走完新版。关于自动执行太快等体验，以用户反馈为依据，不冒充本轮性能或用户测试结论。参考项目中 How Agents Think 的 README 已核对，在线交互未实测。

本文件是新的设计建议，不是已完成实现。与旧报告冲突时，取消工厂世界观、角色、默认连续播放等条款以本文件为准；原有事实校验、数据不重复写入、旧记录兼容等可靠性约束继续保留。

## 1. 为什么前几轮仍然难懂

现在首页已经把文字改成“带着三条消息，走进 Agent 工厂”，并且增加了输入输出预览。但它仍先邀请用户参观一个空间，而不是明确解释：这里可以学会什么、为什么值得学、第一次该做什么。[R1]

前几轮的主要矛盾不是 3D 精度不够，而是多了一层需要学习的翻译：用户先认识机器、车间、人物，再把这些比喻翻译回上下文、工具、模型、持久化。把所有设施做成相似的桌台或机柜，还会削弱它们在功能上的差异。

本轮不再以“多一层空间包装”为主要手段。改成直接表达功能：容量用容器，历史用归档页，技能用步骤卡，工具调用用带目标的请求卡，返回结果用附来源的回执。

删除人物不是删除引导。引导由当前问题、动作次序、就地短注释与清楚的主按钮承担。

## 2. 值得参考的实际项目

以下不是效果排名，也没有完成对每个站点的浏览器交互测评。提取的是已经核对的设计机制；这些机制在本项目中的效果仍需验证。

| 参考 | 核对到的机制 | 应借鉴 | 不照搬 |
|---|---|---|---|
| How Agents Think | README 描述三个手写场景、计划/工具调用/容量指示、可拖动时间线，画面由 `stateAt(scenario, ms, choices)` 导出。[R2] | 把运行过程做成可暂停、倒回、分支对照的教材；情景与播放状态分开 | 终端式文本密度、约一分钟的节奏、不加说明的“内心独白”；不要把手写旁白当真实隐藏推理 |
| Bartosz Ciechanowski — Gears | 原文用局部动画、播放暂停与滑块展示速度、传动等关系。[R3] | 直接展示机制；没有必要的外壳就不要画；一个操作带来可见变化 | 整篇长文与机械内容本身；并非原站每张图都为三维 |
| Red Blob Games — Introduction to A* | 拖起终点观察结果、逐步观察搜索边界、对照不同规则。[R4] | 先显示输入与输出，再让人修改一个条件看因果；单步回看 | 全部算法细节与代码；首访不应变成代码教程 |
| Transformer Explainer | 可输入文本、调整采样参数、逐层解释结构；页面说明使用 GPT-2 small。[R5] | 同一整体中展开局部，保留输入数据身份；实现细节按需看 | 默认满屏模块、数学细节与大模型内部结构；本馆关注 Agent 外部运行循环 |
| LOOPY | 用圆和箭头建立可运行的因果模型，并通过“会怎样”问题探索。[R6] | 有反馈回路的总体视图，而非单向传送带 | 因果强弱传播不等于 Agent 的请求/响应事件；不照搬其传播语义 |
| The Evolution of Trust（补充） | 先做选择，再观察反馈，随后变化条件与进行可选沙盒实验。[R7] | 让用户先预测再验证；沙盒不阻塞主线 | 人物造型、大量角色和完整游戏化包装 |

最推荐组合：**How Agents Think 的运行回放 + Gears 的机制表达 + Red Blob Games 的局部可操作性**。不是再找一个工厂模板。

这些作品属于“Explorable Explanations / 可探索式讲解”这一类学习产品；可以在其项目集合中继续寻找互动形式。[R8]

## 3. 首屏：先承诺学习收益，立即接到一个具体任务

### 建议文案

**AI 不只会回答。它是怎么把事情做完的？**

亲手走一遍：让它查资料、核对消息，再看看 Hermes 如何把经验带到下一次。

任务卡：
> 帮我核对这三条消息，整理成一份有来源的简报。

主按钮：**看看它怎么做 →**

小字：互动教学演示 · 无需代码 · 不连接真实模型

### 首屏行为

- 不先出现全工厂、全地图或五个章节。
- 展示三张有短标题的资料卡和一张待生成的结果卡；不要只写“A/B/C”。
- 不预先把完整答案塞在首屏，不让用户读完一份报告才进入体验。
- 第一次点击直接进入资料如何进入当前工作区的场景，没有欢迎弹窗和导师自我介绍。
- 首屏只能有一个高权重主操作。恢复进度和深入阅读可以保留为低权重文字入口。
- 不要求登录、填写昵称、选择学习身份、先学快捷键或选择模型。

### 学习承诺

体验后，用户应该能解释：模型与工具怎样配合；为什么结果会使 Agent 返回继续处理；上下文为何需要整理；Hermes 怎样在新会话中使用已保存的资料和方法。

主任务只是例子。网站的价值不是“替用户生产一份简报”，而是让人看懂这种执行过程。

## 4. 页面：一张稳定舞台，不再游览九台机器

主视图使用固定斜俯视或近正交的 2.5D 布局。可以继续用 Three.js，但不要求全场景像真实建筑。

三个稳定位置：左侧是用户目标和输入，中间是当前工作过程，右侧是结果。工具入口出现在中间下方，历史与长期资料在需要时从边缘展开。不会因为解释不同概念就让整个空间重新排列。

初始只展示任务卡与当前资料。随后出现模型输出的请求、工具入口、返回回路；最后才展开持久资料。系统全貌随着真实需要逐步长出来，而不是首屏扔出完整架构图。

默认界面只有：当前问题、主要演示、一个主操作、一个“为什么”。

没有常驻小人、导师头像、01/05、1/2/3/4/5、悬浮长文、九个 Idle 标签或整片装饰流光。术语和来源进入局部深入面板。

### 总览与导航

主舞台本身就是工作流，不再另放一幅相同的常驻大地图。进入上下文等局部特写时，右上角出现小型“当前位置”图，标明这仍是同一个循环中的一部分。返回总览后自动收起。可在更多中提供按概念定位的目录，但不是默认章节工具条。

结构布局保持稳定。语义拓扑与空间坐标都来自一份配置，不做两套独立流程。

## 5. 用什么表示各个概念

| 概念 | 推荐表现 | 动作本身需要说明什么 |
|---|---|---|
| 用户目标 | 一张固定的任务纸条 | 任务是约束，不会被工具擅自改写 |
| 当前上下文 | 有容量边界的透明托盘 | 当前提供给模型的资料与所有档案不同 |
| 模型 | 清楚标为“模型”的简洁区域，只有输入和两类输出 | 输出是回答或行动请求；不要假装可直接看到内部推理 |
| 工具调用 | 有动作与目标的请求卡 | “读取公告 A1”是请求，不是已经读完 |
| 工具执行 | 对应能力的小入口，例如网页页签/文件抽屉 | 请求进入后才出现执行动作和回执；不需要模拟工人 |
| 工具结果 | 带编号、来源及状态的回执卡 | 结果回到当前资料，再影响下一步 |
| 历史 | 归档叠页或可翻阅记录 | 保存过不等于当前模型已经看见 |
| 长期记忆 | 可检查的少量便签 | 事实与偏好可以被维护；不是模型权重 |
| Skills | 可展开的步骤卡 | 是可复用方法与资料，读取不等于自动正确执行 |
| 压缩 | 直接作用在中部资料上的提炼动画 | 多页变成新的摘要表示，有信息取舍，不是文字缩放 |
| 结果 | 展开为可读草稿 | 能沿来源标记回到证据；生成不等于发布 |
| 轨迹 | 默认折叠的时间记录 | 记录可观察行为，不冒充真实隐藏思考 |

原则：一个道具若需要解释“这台机器其实代表什么”，且不能用形态或动作直接说明，应优先改成更简单的功能表示。

## 6. 第一次任务：让返回回路真正被看见

教学范围明确为一种典型工具型 Agent 循环，不声称所有系统都必须按同样实现。预定义工作流与模型动态决定工具使用的 Agent 也不是同一件事。[R9]

建议保留以下因果链：

用户目标 → 组装本轮输入 → 模型输出工具请求 → 运行时执行工具 → 返回结果加入输入 → 再次请求模型 → 可能继续调用工具或输出回答。

运行时是包住请求、执行、回填与下一轮调度的边界，不必另造一台复杂调度机器。深入时才展开它的职责。

### 示例场景

三份自编材料中，两份指向同一件事，另一份包含夸大表述。原始公告尚未读入。

- 用户点击“看看下一步”。模型生成“读取原始公告”的请求卡。画面停住，可见“有请求，还没有结果”。
- 用户播放这段。请求到达工具，工具返回原文。回执沿回路线回到当前资料，不直接飞进最终报告。
- 新旧文字并排短暂展开：“全面开放”与“接受试用申请”产生冲突。发生修正后停住。
- 用户继续观察。重复内容合并，结果侧形成有来源的简报，不强行凑足条数。

这条主线应主要让人理解返回、修正和继续，而不是学习多个名词。

### 一个就够的可选干预

在取得原文处提供“换成读取失败的结果”。点击进入明确标记的教学分支：错误回执返回，系统可能换来源、请求补充信息或停止，不能仍沿成功动画交付同样结果。

不要用固定剧本证明模型一定正确。说明是馆内受控演示；技术机制依据官方资料，任务选择与结果为教学脚本。

“看下一步”是控制教学镜头，不是声称真实 Agent 每次工具调用都要用户批准。真正的权限审批应使用不同标签。

## 7. 速度：从连续播放改成“动作自动，理解停住”

默认采用语义单步，不是默认整个任务连续播放，也不是让用户点击每一个动画帧。

一段动作包含准备、动作、结果三个阶段；用户只需按一次“看下一步”，整段完成后停在结果。

必须停住的位置包括：首次工具请求、首次结果返回、证据改变结论、容量接近阈值、压缩后的对照、新会话资料加载。

建议起始动画预算：普通交接约1.5–3秒，复杂信息变换约3–6秒，镜头局部变化约0.4–0.8秒。它们是原型参数，不是强制门禁或研究结论。结果不设消失倒计时。

用户可选“连续观看本段”，但跨新概念仍停住。速度选择只影响运动，不强迫用户按比例阅读。

支持重播与时间位置回看；关闭页面或切到后台后暂停教学时钟。单纯降低到0.5倍不是根本方案。

### 循环播放的边界

循环示意只重播可视化，不重复查询、保存资料、产生实际事件。画面标明“动作示意”。动作完成后以清楚的结果状态等待，不让所有节点假装永远运行。

## 8. 上下文：保留容器与夯实手感，但不能暗示无损

用户提出“容器逐渐装满，再被夯实”的方向适合展示容量变化。但必须展示**旧内容变成新摘要**，而不是只把同样的文字缩小挤紧。

### 演示对象

透明容器里的卡片就是当前输入。原始记录以相同编号保存在容器外的归档区。保护区域先标“任务与约束”“近期交接”；Head/Tail 的正式名称放在追问里。常驻规则与所选保护策略按核实版本区分，不宣称全系统永久不变。

### 过程

1. 初始少量卡片，清楚看到剩余容量。
2. 追加查询结果、比较记录、重复过程等卡片；每批有清楚的来源与类型。
3. 一批一批增长，接近演示阈值时只强调容量刻度，不做刺耳报警。
4. 在阈值处暂停：“再加入一批，接下来放哪里？”
5. 用户播放整理。简单压板或扫过的提炼条直接作用于中部卡片，不增加一座复杂机械装置，也不出现工人。
6. 中间卡片被归并为一张可读摘要。文字内容随之变化；原始卡片的历史副本仍在。
7. 余量增大。保留压缩前/后的摘要与原文入口；结果稳定停留。

可操作项：追加一批、整理、回到刚才、比较摘要。首层不要直接塞模型Token参数与六个阈值滑块。

### 信息真实性

- 示例可以使用100个教学容量格，但不标作真实Token；阈值标“本次演示设置”。
- 短简报不会被硬演成自然耗尽超长窗口；扩展显示“同一任务继续调查多轮的教学分支”。
- 压缩器的职责是生成更短表示，不是缩小字体；可能遗漏约束或进度。Hermes内建压缩文档将默认方法描述为有损摘要，并且支持可配置/可替换策略。[R12]
- “保护首尾”是具体策略的示意，不能宣称所有Agent都永久保留某几条。
- 示例摘要必须真的包含关键约束与未完成事项，而不只显示彩色方块。

局部追问可以比较两份摘要：一份保留“仅接受试用申请”，另一份误写“已经开放”。让人看到缺失条件如何影响后续结果，而不是只背“压缩有损”。

## 9. Hermes 的特点：让同一张舞台跨过一次新会话

不再新建一个“Hermes 特殊工厂”。也不要用“普通Agent没有记忆”的稻草人比较。

第一次任务完毕后，任务结果仍在右侧。出现一个短操作：“把这次方法留给下次”。明确这是虚构案例中的保存决定；站点真实用户资料是否持久化仍按已有授权规则执行。

随后进入新会话。旧工作区退出当前输入，长期资料留在舞台边缘。新任务提出了不同要求，例如给研发读者增加技术细节，并核对上次未确认的变化。

把三种机制分别演清楚：

- **原生记忆**：已保存的用户/环境资料在会话开始时进入系统提示快照，不应一概画成向量搜索后才读到。[R10]
- **技能**：相关方法完整内容在需要时加载，不是把所有手册自动全部灌入上下文。[R11]
- **历史检索**：需要追查旧结论时，按需取得相关旧记录，不把整段旧聊天偷偷搬回来。[R10]

屏幕表现为“偏好便签进入输入、步骤卡按需展开、历史记录经查询返回”，而不是三个一模一样的记忆水管。

当前明确要求优先于相冲突的旧偏好；旧事实必须核实。技能可能不适用，记忆可能过时，读取不保证成功。

可以加一个对照开关：“本次不使用跨会话资料”。标明比较对象为本案例中未配置这些能力的最小工具型Agent，不代表其他框架能力上限。

不承诺存下偏好后必然更少工具调用、更快或答案更好。演示应证明“哪些资料被实际带入并影响了下一步”，不是伪造性能提升。

若用户拒绝保存，则下一轮如实为空。可提供明确标注的临时教材分支“看看保存过的情况”，不能暗中替用户保存，也不能在0条偏好时讲“它记住了你”。

## 10. 深入方式：问对象，不再问一个角色

默认一个短问题，例如“它为什么又回来了？”或“为什么这里变空了？”

点击卡片旁的“为什么”，打开短解释与可选深入层。主线、程序员细节、官方依据共用同一事实来源，不维护两套互相漂移的课程。

上下文处可追问：整理会丢什么、原始记录去哪了、为什么提前整理、Hermes怎么选保护范围。

工具处可追问：模型是否执行了命令、工具失败后谁安排下一步、工具成功是否意味着任务完成。

保存处可追问：记忆和技能有何不同、下次何时读取、是否更新了模型权重。

追问只改观察状态，不改业务状态；退出后回到原帧、原对象和原问题。预编问答如实标明，不伪装自由实时聊天。

## 11. 报告与测验：保留成果，取消仪式负担

默认结尾展示“你刚刚看懂了什么”，让用户用一个新情景判断，例如“工具读取成功了，但内容是旧版本，任务完成了吗？”

详细报告和已有纪念证明放到“带走这次学习”中，不再需要完成入场登记、实习流程或感谢人物的剧情。用户选择结束即可。

截图必须为实际看到的机制画面。报告区分看过、操作过、回答过，不能把停留或完成播放自动写成掌握。

不需要强制下载或考核才能离开；原有本机记录、原始来源、错误复习与可选测验可以继续用。

## 12. 实现建议：更换表达层，不再次重写所有业务

继续复用已经正确分离的任务、导览、学习状态和存储机制。不要为了新视觉重写历史兼容、报告、授权和题库。

建议增加或收敛为以下职责（名称为建议，不代表当前文件已经如此组织）：

- `scenario`：固定教学材料、分支和可观察事件；不依赖相机。
- `presentation`：由事件、局部时间、当前分支与查看范围导出画面；可重播、可倒回。
- `stage`：容器、卡片、回路、归档页等少量视觉对象；不含业务写入。
- `lesson`：当前自然问题、最短说明、深入入口；不以编号章节作为默认UI。

可借鉴 How Agents Think 的 `stateAt(scenario, ms, choices)` 思路，令可视状态由输入推导；但只用于教材/回放，不把真实外部操作假装能倒回。[R2]

关键约束：业务副作用只发生一次；播放时间、相机时间、学习记录分别管理；回看不改变原事件；同一证据编号贯穿卡片、摘要和报告。

技术选择：Three.js可继续承载立体容器与卡片；文字和按钮使用HTML，简洁回路线可用SVG。不要为了统一技术而让小字号长文变成三维纹理。并非必须把全站改成2D，亦不必升级渲染引擎。

## 13. 明确废止的旧要求

| 旧要求 | 本轮新约束 |
|---|---|
| 每个部件一台设备/一座车间 | 按功能使用卡片、容量容器、步骤纸等直接表示 |
| 导师小人带路、工人执行 | 无角色主线；引导由动作与短解释承担 |
| 数字1–5常驻导航 | 去掉；局部仅显示当前问题，概念目录按需 |
| 自动飞向每站并连续讲解 | 固定舞台、局部展开；默认语义单步 |
| 26秒固定压缩影片必须看完 | 增长、阈值、整理、结果可单独控制与回看 |
| 背景一律透明 | 首先减少无关对象；局部聚焦时再降权必要背景 |
| 永远显示全局地图 | 总览就是主舞台；局部放大时才显示定位图 |
| 进工厂—报告—考试—证明—告别的必经流程 | 完成机制理解即可结束；报告和自测为可选成果 |

这些修改不是进一步堆砌选项，而是更改默认体验。

## 14. 实施前先验一个小样，不再一次重做全站

第一批只实现三段：

A. 首屏接任务→产生请求→取得结果→结果返回→改变下一步。  
B. 卡片逐批增长→接近阈值→摘要提炼→保留结果对照。  
C. 旧会话退出→保存资料进入新会话→技能按需读入→继续查证。

暂不重做考试、证书、报告美术，不扩展新任务。

形成性测试由第一次接触的人操作，开发者不口头解释。观察用户能否回答：

- 开场时知道这是学习Agent的网站，还是以为是新闻工具/虚拟参观？
- 谁提出动作，谁执行动作？
- 工具结果为什么要返回，而不是直接成为最终答案？
- 压缩后哪些内容真的变化，原始记录是否还在？
- 新会话为什么能用到某些旧资料？没有保存时是否知道缺什么？
- 是否需要不断追着动画阅读，错过后能否回看？

这些是验收问题，不是已经证明的效果。小样若需要开发者不断解释，就先改表现，不再增加讲解字数。
