# Hello Hermes 工厂实习馆：调研分析与改造报告

## 从“参观很多部件”到“看懂一次工作，以及下一次为什么不同”

**报告日期：2026-10-29**  
**研究对象：** hello-hermes 在线工厂、公开仓库和既定视觉聚焦方案。  
**公开源码快照：** `56a74b2294d345ab93203724f0a1dbbe5c47e5d0`。  
**报告性质：** 产品、教学与交互改造建议；不是已经完成的改造或用户实验结果。

> 核心建议：保留工厂、导师、动态机制、追问、照片、报告和结业仪式；把体验重构为“一次委托的完成 + 一次新会话中的复用”。主线只承担必要理解，深入问题和实现依据按需展开。减少的不是知识，而是同一时刻要求用户处理的东西。

---

## 0. 执行摘要

当前项目已经有可继续打磨的产品基础，不应再从零换一套展馆。真正需要改变的是内容组织方式：从“按模块分配站点”转向“由任务中的问题引出模块”。

本报告建议做六项关键调整：

| 调整 | 要解决的问题 | 预期产物 |
|---|---|---|
| 把礼盒生产改为资料核验与简报委托 | 实体制造与记忆、上下文之间需要反复解释隐喻 | 一条无需额外圆场的任务主线 |
| 一次完整任务后，增加一个短的新会话片段 | 只参观一次任务，很难看到跨会话记忆和技能复用 | 可观察的 Hermes 学习与复用闭环 |
| 主线收敛为五个观察章节 | 八站逐站讲三段，容易变成空间化长文档 | 少量关键现象、连续的因果关系 |
| 所有扩展使用同一个追问面板 | 角色切换、弹窗和多层模式造成上下文切换 | 普通人和程序员共享入口、深度可选 |
| 视觉聚焦改为“减弱背景、选择性透明、运行状态独立” | 全场透明、持续转镜头和遍地流光可能继续抢注意力 | 可读的 3D 工作现场，而非展示特效 |
| 报告与测试围绕理解证据，而非收集进度 | 走完、点过、拍过，不代表能解释或迁移 | 能复述、能预测、能区分边界的学习成果 |

**最优先的工作不是做更多场景，而是做一个能讲通、能回放、能验证的纵向切片：**

收到不完整资料 → 获取原始来源 → 根据反馈改变动作 → 管理工作上下文 → 交付有依据的简报 → 保存合适的经验 → 新会话中重新读取并使用。

本报告中的时长、数量、透明度、通过率等数值，除明确标注现站事实或标准要求外，都是**待验证的产品起始参数**，不是研究证明的最优值。

## 1. 调研范围、证据与限制

### 1.1 实际查了什么

本次读取了在线首页、公开仓库的 README、实习馆蓝图、版本来源说明，以及 `content.mjs`、`engine.mjs`、`scene.mjs` 等关键文件。公开快照仍以礼盒订单为主线；站点已有八站、导师问答、独立上下文实验、照片与报告、十题测试和纪念证明。[S01–S06]

技术部分交叉检查了 Hermes 官方的 Agent Loop、工具运行时、持久记忆、Skills、会话存储、上下文压缩、轨迹和定时任务文档；同时用 LangGraph 的官方记忆文档校正“只有 Hermes 有记忆”的错误对比。[S07–S16]

教学和体验依据包括渐进呈现、多媒体学习的信号提示与分段、可探索解释、检索练习，以及 W3C 的动态效果控制要求。另参考了沉浸式学习实验，但不把头显 VR 的实验结论直接套成浏览器 3D 的结论。[S17–S25]

### 1.2 没有完成什么

本次没有完成交互浏览器的全流程实测、真实设备帧率测试、移动端触控测试或新手可用性测试。浏览器连接不可用，因此对布局、遮挡和运动的判断属于**基于页面、源码和设计方案的专家审查**，不是亲测结论。

此前讨论过的“关注度与运行状态分离、三层聚焦、关系线过滤”等原则，作为继承约束；不能仅凭对话就认定它们全部已经部署。报告不修改、提交或发布项目代码。

项目已记录固定 Hermes 版本与提交作为教学依据。在线官方文档可能继续变化，不能用网站最新描述自动覆盖项目已核实版本。后续实现应逐项维护版本与证据，而不是把本次阅读等同于全量源码验证。[S03]

## 2. 现状诊断：不是缺功能，而是主线还没有替用户减负

### 2.1 应当保留的资产

现有产品最值得保留的是：有状态的本地教学世界、诚实说明不是实时 Hermes、导师引导、可选问答、原始记录与工作资料分开、实际场景截图、可导出报告、本机存档、可重试且可退出的考核。现有引擎还明确防止回访时重复领料，区分完成制作与授权发货。[S02、S04、S05]

这些并不是需要全部重做的缺陷。新主题应当复用这些能力，只替换业务对象与教学编排。

### 2.2 真正的五个结构性问题

| 观察 | 判断 | 建议 |
|---|---|---|
| 礼盒订单包含数量、预算、主题色、食品与收件人等字段 | 进入 Agent 概念前，要先理解一套制造业务 | 删除与学习目标无关的业务配置 |
| 上下文压缩被放入独立长订单实验 | 避免了错误原理，但主任务和重点知识分成两条故事 | 用信息工作自然产生资料积累；不假称简单任务必然压缩 |
| 八站各有三段主讲，附带多个问题 | 站点数与文案量容易成为默认学习负担 | 按“当前疑问”组织章节，不按组件数量组织章节 |
| 主线在第一张订单验收后结束 | 记忆、Skills 主要是被介绍，复用价值没有完整显现 | 用新会话短片段证明“写入之后发生了什么” |
| `enterStation` 同时承担参观推进和部分业务动作 | 回访、追问与未来分支容易受到参观顺序约束 | 任务事件驱动执行，导览选择观察位置 |

最后一项不是说现版会重复扣料——它已经有幂等保护。问题是架构耦合：**到了哪个房间，不应该成为 Agent 为什么执行某个动作的原因。** 当前写法适合小型模拟，下一版的双任务与回放需要进一步拆开。[S04、S05]

### 2.3 一个明确的取舍

不要再把更多知识点变成更多房间。WAL、FTS5、ToolRegistry、MCP、RL 都值得学习，但并不都值得占用第一次参观中的独立章节。

完整不等于默认展示所有实现细节。完整应当意味着：**从目标、动作、反馈、信息管理到交付，因果链不缺；想深入的人能够找到细节。**

## 3. 调研结论：Less is more 应具体删掉什么

### 3.1 可以转化为设计规则的研究与案例

| 依据 | 能支持什么 | 对本项目的具体应用 | 不能推出什么 |
|---|---|---|---|
| Nielsen Norman Group：渐进呈现 | 先呈现主要功能，再提供明确的深入入口 | 主线只放当下必要信息；扩展集中在一个面板 | 不是把所有重要内容藏起来，也不是无限嵌套 |
| 多媒体学习中的连贯、信号提示、时空邻近原则 | 减少无关材料，突出重点，使讲解与对象接近 | 文字靠近对应机制；同一时刻只突出一个变化 | 不是装饰越少越好到失去空间定位 |
| 分段原则 | 由学习者控制分段进度有助于理解 | 自动带路，但关键段落可停、可重播、可继续 | 不是强迫每句话都点击下一步 |
| Explorable Explanations | 通过改变条件、观察后果来理解模型 | 允许“去掉来源”“丢掉约束”“关闭跨会话资料”对照 | 不是只要有滑块就算有效互动 |
| 沉浸式学习实验 | 身临其境与学习表现不是同一指标 | 分别测“喜欢”和“学会”，不要只测停留时长 | 不能断言浏览器 3D 一定比二维差 |
| 检索练习研究 | 主动提取知识有助于延迟保持 | 结尾用情境题和简短解释，而非只展示总结 | 不能保证本馆某套题必然产生同等效果 |
| W3C 动态控制要求 | 自动运动和非必要交互动画应可控 | 暂停、减少动态、稳定镜头和键盘替代路径 | “沉浸感”不能成为剥夺控制的理由 |

上述依据支持设计方向，不证明本馆采用后必然达到某个完成率。[S17–S24]

### 3.2 从成功案例借什么，不借什么

Transformer Explainer 允许从具体输入观察模型结构中的变化；值得借鉴的是“同一份数据贯穿视图”，不是把大量技术细节同时搬到首屏。Explorable Explanations 的价值在于让条件变化引起可解释后果，值得借鉴的是可验证性，而不是交互形式本身。[S20、S25]

对本馆而言，一条始终可辨认的资料卡，比几十条没有语义的发光粒子更有教育价值。

### 3.3 建议设立“注意力预算”

每个主线段落，默认只有：一个当前疑问、一个主要动作、一个可见结果、一个主操作。

起始约束建议为：同屏最多一个主焦点、两个与当前事件直接相关的配角；每段主讲引入不超过两个新术语；初始只展示两个相关追问。它们是编辑约束，不是认知科学常数。

凡是不能回答“它帮助游客理解了哪条因果关系”的元素，移到扩展层或删除。旋转摄像机、跑动工人、流动粒子、音效、徽章也适用这条标准。

## 4. 新的产品结构：五个观察章节，一条委托主线，一个复用尾声

### 4.1 定位

**产品名仍保留：Hermes Agent 工厂实习馆。**

对外描述建议改为：

> 跟着一份委托，看模型怎样借助工具完成工作，再看看 Hermes 如何把这次经验带到下一次。

工厂只是组织观察的空间隐喻，不是另一套需要学习的制造业务。真实概念使用稳定名字：上下文工作台、会话档案、用户资料、技能手册。不要为同一概念不断创造“记忆晶体、经验电池、智慧仓库”等别名。

### 4.2 第一个案例：把几份消息做成可信简报

默认委托建议直接给出：

> 这几份材料有点乱。请核对原始来源，合并重复消息，整理成不超过三条的简报。区分已经确认和还不确定的内容。只生成草稿，不替我发布。

资料必须是**不完整线索**，而不是已经给齐全文和答案的三篇文章。否则强迫 Agent 再去搜寻会失去必要性。

建议固定教材包含：两份指向同一事件的转述、一份把“申请试用”写成“全面开放”的摘要，以及可由工具取回的公告和补充说明。所有材料使用自编虚构内容并清楚标识，不依赖当日新闻、登录或外部 API。

不强制凑满三条。发现只有两条独立、足够可靠的消息，就交付两条，并说明原因。这能把“满足目标”与“机械填满格式”区分开。

### 4.3 首屏先给价值，再给入口

首页展示一个明确标注为样例的成品缩略图：两条简报、来源、未确认项和“尚未发布”状态。访客先知道自己最终会得到什么，再点击“跟着这份委托参观”。

昵称可以稍后填写；删掉入场前的预算、库存、配色、收件人表单。选择受众偏好只保留一个可选项，例如“偏业务影响 / 偏技术细节”，且必须实际改变简报侧重点。没有改变后果的设置不保留。

### 4.4 五个观察章节

| 章节 | 游客此时的问题 | 必须看见的事件 | 必须形成的理解 |
|---|---|---|---|
| 1. 接到委托 | 为什么不直接写完？ | 当前资料不足，模型提出获取原始来源的请求 | 模型提出动作，运行时调度，工具实际执行 |
| 2. 查证与回路 | 查回来以后为什么又改主意？ | 两篇报道指向同一公告；工具结果改变下一步 | Agent 根据反馈推进，不是固定一次走完的传送带 |
| 3. 有限的工作台 | 资料都保存了，为什么还要整理？ | 工作上下文与档案分开；长过程回放展示整理前后 | 存着不等于本轮看着；摘要可能丢失信息 |
| 4. 交付并留下经验 | 做完之后到底留下什么？ | 交付有来源的草稿；分别保存历史、适当偏好与方法 | 当前结果、长期资料和模型权重不是一回事 |
| 5. 新会话中的复用 | 为什么这次不用从头交代？ | 旧上下文退出，新会话读入资料；按需读技能并查历史 | Hermes 的长期机制通过读取与复用产生价值 |

这些是五个**观察章节**，不要求场景只有五台设备。现有八个区域可以合并讲解，或保留为深入查看的小部件。

### 4.5 双任务不是让用户重走两遍

第一段走完整流程。第二段只展示发生变化的部分：新会话出现、适当资料被读取、技能按需加载、旧消息被查回、当前新要求覆盖旧偏好。

第二份委托例如：

> 这周继续，但这次给研发同事看，可以多一点技术细节。上次那项还在申请试用的功能，现在有什么变化？仍然只做草稿。

这里既能演示复用，也能演示**复用不等于照搬**。前次的事实需要重新核实；本次的明确要求不能被旧偏好覆盖。

建议主线设计目标为 12–15 分钟，不含自由追问和考核。是否能达到、是否影响理解，需要实际测试；不能靠加速字幕来达成。

## 5. 怎样准确展示 Hermes 与“常规 Agent”的区别

### 5.1 先定义比较对象

不要出现“普通 Agent 没有记忆，Hermes 有”的二分法。LangGraph 官方文档同样明确支持跨会话长期记忆。这里的教学基线应标为：

**最小工具型 Agent：当前会话上下文 + 模型调用 + 工具执行 + 结果反馈循环。**

这是一种为了讲解而定义的最小配置，不代表所有竞品，也不代表主流 Agent 产品的能力上限。[S15、S16]

### 5.2 主要差异应该发生在行为里

| 维度 | 最小基线演示 | Hermes 默认方案的教学重点 | 必须说明的边界 |
|---|---|---|---|
| 当前任务循环 | 根据工具反馈继续行动 | Hermes 也有这个基础循环 | 不是 Hermes 独创 |
| 跨会话事实与偏好 | 未配置长期资料时需要再次交代 | 有限、可维护的持久记忆与用户资料 | 实际写入、配置与读取才会生效；不是“说记住”就算 |
| 可复用方法 | 本次完成后没有沉淀方法 | Skills 可被创建、更新并按需加载 | 技能不是自动执行器，也不是质量保证 |
| 过去过程的回查 | 不提供跨会话搜索时无法直接查旧过程 | 会话历史与搜索是独立能力 | 存有历史不代表模型每轮看过全部历史 |
| 持续任务 | 可以结束在一次运行 | Hermes 还提供网关、定时任务等集成能力 | 属于扩展，不要求每次任务经过它们 |
| 模型训练 | 不更新权重 | 记忆与技能改进仍不等于 RL；另有轨迹和研究流程 | 训练是独立流程，不是使用一次就变更权重 |

Hermes 官方资料支持其记忆、Skills、会话搜索和运行集成的组合；这些是应展示的工程特色，而不是据此宣称独占相关思想。[S07–S14]

### 5.3 展示“可检查的学习”，不展示“变聪明特效”

正确的可见过程是：

本次发现了可复用做法 → 形成可检查的 Skill 条目 → 实际保存 → 新会话发现相关条目 → 读取 → 在新约束下使用 → 必要时修正。

不应当是：任务结束 → 一颗“经验球”飞进大脑 → 能力等级自动增加。

同样，保存偏好要出现真实的写入事件与条目；读取时展示来源。用户拒绝保存，下一次就不应自动出现那条偏好。本馆可以采用比默认运行更显式的确认设计，但须标注这是教学交互选择，不声称 Hermes 所有写入都必然弹窗确认。

### 5.4 重要但退出主线的内容

WAL 的读写细节、FTS5 倒排索引、向量检索比较、单例与依赖注入、MCP、子 Agent、Cron、RL 都进入扩展层。主线仍要知道工具目录、历史检索、任务边界的作用，但不要求记住技术名词。

尤其 RL 不应成为出厂必经站：它容易让人误以为每次普通任务结束都会训练模型。轨迹与训练在官方架构中也不是会话数据库的一条必经生产工序。[S11、S13]

## 6. 可选追问：深入但不破坏主线

### 6.1 只使用一套入口

不再让访客先选择“普通人模式 / 程序员模式 / 架构师模式”。所有人看同一条任务，使用同一套核心解释。想深入时打开当前部件的追问面板。

首层显示两个与眼前事件相关的问题，另有“更多问题”。面板内可切换“理解原理 / Hermes 怎么做 / 失败与边界”，但不要形成三层连续弹窗。深度是内容层次，不是导航层数。[S17]

### 6.2 哪些可以选学，哪些不能藏

| 必须在主线讲清 | 可以按需展开 |
|---|---|
| 模型与执行器的区别 | 工具 Schema、模块级单例、同步与异步 |
| 根据返回结果再决定下一步 | 超时、重试、并发调度策略 |
| 当前上下文、历史、记忆、技能不是同一种东西 | SQLite、FTS5、向量检索、文件结构 |
| 压缩会改变输入，可能损失细节 | Head/Tail 选择、工具对完整性、阈值与模型差异 |
| 经验复用不等于训练权重 | Trajectory、SFT、RL 与训练基础设施 |
| 新指令与授权边界必须尊重 | 具体沙箱与审批机制、幂等和恢复策略 |

跳过全部追问的人，也必须能理解主线、完成核心考核。不能把答题必需知识藏到“可选”中。

### 6.3 追问的体验合同

打开追问时，保留原来的章节、镜头与演示位置。暂停教学推进；面板明确这是“暂停观察/回放”，不要暗示真实远程工具因此冻结。关闭时回到同一时刻，不重做业务动作，不自动跳过下一段。

回答采用四步结构：**先答问题 → 指向眼前证据 → 给出一个边界 → 返回当前任务。**

例如：“会丢。刚才这份过短摘要漏掉了‘仍需申请试用’。原始公告还在，但如果没有重新查回，模型仍可能沿用不完整信息。我们现在回到公告核对，而不是直接交付。”

### 6.4 暂时不必引入实时 LLM 导师

现有预编问答的诚实标识应保留。优先把状态相关问答编辑好，而不是立即增加开放聊天和 API 依赖。[S01、S04]

自由输入问题可以先检索已审核问答，展示匹配问题供用户选择；找不到就明确说本馆暂未覆盖。不要用固定答案伪装成理解了任意提问。未来接模型时，应使用版本化资料约束回答，并将开放生成与课程已审核解释区分。

## 7. 自然的导师脚本：从现场开始，而不是从定义开始

### 7.1 统一叙事结构

每个章节遵循：**看见现象 → 发现问题 → 采取动作 → 看见结果 → 命名原理。**

避免每站重复“它是什么、为什么重要、适用场景、优缺点”的百科模板。用户是在参观一项正在发生的工作，不是在听九场产品介绍。

### 7.2 四段可直接作为改稿样例的对话

**入口：**

> “这三份材料看起来像三条消息。不过现在还不知道，它们是不是在说同一件事。先别急着写，我们看看原始来源。”

此时出现“读取原始公告”的请求卡。请求进入执行区后才产生结果。第二句讲解再命名：“提出请求的是模型，真正去取资料的是工具，调度负责把它们接起来。”

**工具反馈：**

> “看，这两张卡片都指向公告 A，所以不能当成两件事。另一篇说已经全面开放，但原文只说接受试用申请。我们得修改结论。”

画面同时合并重复来源，保留被纠正的主张和依据。这里展示可观察的决策与证据，不编造模型隐藏推理。

**上下文：**

> “这些资料都存进档案了，但这次交给模型看的只是工作台上的一部分。调查变长以后，工作台需要整理；档案并不会因此自动消失。”

再提供“看一次长过程整理”的可控回放。明确跳过了重复查询和中间轮次，不把三条短消息画成已经塞满真实窗口。

**新会话：**

> “这是新的一次委托，上一轮聊天没有整段搬过来。这里带来的，是已经保存的资料和这次需要的手册。你刚刚要求多一点技术细节，所以旧的简洁偏好不能直接照搬。”

结尾可用一句话收束：“下一次不必完全从零开始，但仍要重新判断。”

### 7.3 语言与角色约束

导师负责解释，不代替模型做任务；工具工人表示程序执行能力，不默认表示独立 AI 子代理；工厂表示系统协作，不暗示真实 Hermes 必须以固定房间顺序运行。

少用空泛赞美、“神奇”“智慧”“自我进化”。每段文字应能回答一个现场问题，删除不能对应画面变化的重复句。技术术语首次出现时附白话名，后续名称保持一致。

## 8. 技术真实性：用少量清晰边界代替大段免责声明

### 8.1 建立三类内容标记

| 标记 | 含义 | 呈现方式 |
|---|---|---|
| 通用原理 | 可用于理解很多工具型 Agent 的概念 | 主讲中的稳定解释 |
| Hermes 实现 | 已核对版本中的具体方案 | 深入面板显示版本、实现摘要、来源 |
| 教学模拟 | 为观察机制而设计的数据与演示 | 画面固定小标签，实验处显示单位与假设 |

安全、授权、数据真实性的关键边界不能只放在“关于”页面。来源版本和实现细节则可以收在深入面板，避免每句话都附一段警告。

### 8.2 必须避免的误解

| 容易画错或说错的内容 | 正确表达 |
|---|---|
| 导览路线就是实际调用顺序 | 路线是讲解顺序；运行由任务事件决定，可循环、等待、跳过 |
| 工厂里有几个工人，就有几个 Agent | 默认表示不同工具；子 Agent 另作明确概念 |
| 工具目录负责授权所有动作 | 目录管理能力描述；权限和执行约束另有职责 |
| 每次任务都会读取全部记忆、全部技能 | 记忆注入与技能按需加载有不同策略；可用不等于已读取 |
| 说“记住了”就产生了持久记忆 | 必须有实际写入和后续读取的证据 |
| 压缩会物理删除所有历史 | 本轮输入与已持久化资料分别管理；保留范围需按版本核对 |
| Head/Tail 永久逐字不变 | 本次策略可保护部分首尾；Tail 会滚动，还需处理工具调用配对等边界 |
| 达到某个百分比就一定更好 | 阈值与模型、估算、预留、配置和引擎有关；展馆数字不是普遍规则 |
| 有档案就能自动恢复任何副作用 | 恢复依赖实际状态、幂等设计与外部确认 |
| 技能保存意味着模型权重更新 | 技能是之后可读取的程序性资料；训练权重是另一流程 |
| 已生成简报等于已发送 | 交付草稿和执行外部发送分别授权 |
| 确定性模拟的成功率代表 Hermes 性能 | 模拟说明机制，不是对真实模型的基准测试 |

这里的关键边界分别由官方运行循环、工具、记忆、技能、压缩和存储说明支撑；具体实现仍应绑定项目版本。[S07–S12]

### 8.3 上下文展项的准确版本

可视化至少分出：常驻指令与工具说明、保护的前段内容、可整理的历史、近期完整交接。不要把“用户订单”默认等同于系统提示，也不要把所有历史视作都可丢弃。

主线只讲三个判断：容量有限、摘要有损、原始记录与当前输入分开。Head/Tail、窗口大小、输出预留、重压缩、工具配对留给追问。

继续使用 100 格、70 格触发线也可以，但应明确为**缩比教学模型**；不把每个方块说成一个真实 Token，不把阈值写成 Hermes 恒定默认值。提供“摘要漏掉试用条件”的对照，比让用户反复拖阈值更能形成理解。

官方压缩机制存在配置、保护段、摘要重组和配对清理等规则，因此“Head/Tail 永远原样不动”不宜成为课程口号。[S12]

## 9. 交互与视觉：从不断展示，到恰好引导

### 9.1 主界面只承担一件事

桌面默认保留：当前章节、一条很短的委托要求、中央场景、导师当前讲解，以及“继续 / 追问”。暂停、回到全景、退出始终容易找到；完整路线、照片、档案与设置收进统一的次级入口。

不同时常驻地图、任务面板、全文日志、导师聊天、参数面板和照片列表。它们都合理，但没有必要一起出现。

移动端使用固定观察位加底部讲解面板，不要求用户先学会第一人称行走。自由探索仍可提供，但不成为完成学习的前置条件。

### 9.2 修订此前的聚焦规则

保留“关注度”和“运行状态”两个独立维度，并进一步收紧：

| 对象 | 默认处理 |
|---|---|
| 当前讲解对象 | 清晰、稳定描边和名称；不因为被讲解就假装工作 |
| 与当前事件直接相关的部件 | 正常或稍低对比，显示必要的进出关系 |
| 远处无关部件 | 降低饱和度、亮度和标签密度，减少装饰动画 |
| 挡住视线的屋顶、外壳、前景设备 | 局部淡出、剖切或选择性透明 |
| 实际运行的部件 | 小幅核心脉冲、真实机械动作或状态标识 |

**不再把全场低透明度当成唯一实现。** 透明叠层会暴露背后的更多线条，可能反而更乱；Three.js 透明物体也有排序和深度处理问题。[S24]

优先顺序建议为：减少无关标签 → 降低背景对比 → 隐藏无关关系线 → 对遮挡物做透明/剖切。焦点使用轮廓，运行使用局部运动，避免二者都靠整机发光表达。

当前 `scene.mjs` 使用共享材质；实现局部淡化前，要隔离部件材质或采用独立效果参数，不能直接把共享材质的透明度作为每台设备状态。[S06]

### 9.3 相机在转场时移动，在理解时稳定

自动带路保留，但自动环绕不应持续贯穿阅读和思考。转场结束后停在预设的无遮挡观察位，用户愿意才拖动查看。

普通转场可先尝试 0.8–1.6 秒；跨区域在确有空间解释价值时适当延长。精确时长应由舒适性测试决定，不要为“像参观”强迫用户反复观看长距离飞行。

用户手动操控后暂停自动镜头；只有点击“跟上导师”才恢复。支持 `prefers-reduced-motion`，减少动态模式用切换观察位和静态前后对照完成同等教学内容。非必要动画的关闭、自动运动的暂停应按 W3C 要求设计。[S22、S23]

### 9.4 每一条流动都要有含义

关系线表示可能连接，流动数据表示此刻发生的交接。两者不能混用。

资料卡从工具返回时，显示“公告 A”；记忆读入时，显示“已保存的受众偏好”；工具调用与返回有不同方向；轨迹记录是旁路，不是一条要求所有任务走到 RL 的末端传送带。

当某次请求失败，返回错误卡，而不是让绿色光点照常到达终点。用户应能追踪同一张卡片，知道它由谁产生、去哪儿、改变了什么。

### 9.5 完整体验还包含“不顺利的时候”

模型与工具演示尚未完成时不能显示成功交付。断点恢复不能重复业务动作。WebGL 不可用时保留等价的文字/二维观察；截图失败标记缺失，不补造图片。导出失败可以重试；清除本地记录需要明确确认。

键盘需要能够完成主线、追问、测试和退出；关闭面板后焦点回到触发按钮。颜色不能是状态唯一依据，Canvas 之外要有可访问的文字状态与操作。

## 10. 学习成果：从“看过”变成“能解释、能判断”

### 10.1 核心能力合同

| 学习成果 | 体验证据 | 考核方式 |
|---|---|---|
| 区分模型、调度与工具 | 请求卡出现后，执行器才工作 | 判断“请求已经生成”是否等于执行完成 |
| 解释反馈循环 | 原始公告改变了结论和下一步 | 给新错误结果，预测合理下一步 |
| 区分上下文、历史、记忆和技能 | 同一任务的四类资料有不同位置和读取时机 | 把新信息放到合适位置并说明理由 |
| 理解压缩的价值与风险 | 短摘要遗漏条件，回查补救 | 判断哪些条件与来源不能因摘要而忽略 |
| 解释 Hermes 的长期机制 | 新会话中有可检查的保存与读取 | 说清改变了哪份资料，没有改变什么 |
| 尊重交付与授权边界 | 草稿已完成，发布状态仍未授权 | 判断是否可以顺手外发及其依据 |

### 10.2 考核可以变短，但不能更浅

建议默认六道核心情境题，保留开发者扩展题作为选项。沿用可回访、可重试、无倒计时、退出不受阻的设计。通过线可以暂沿现有 80 分，但它是课程规则，不是职业能力认证标准。[S02]

题目不要只问“FTS5 是什么缩写”。更有价值的是：“历史已经存下来了，新会话为什么还是答错？”正确解释应涉及是否读入、检索是否找对、信息是否过时，而不是把问题全归给模型。

首次作答和复习后的最佳成绩分别记录。答错后解释机制并定位到相关观察片段；复测换一个等价情境，不只重复原题。检索练习研究支持主动提取的价值，但本馆的题目是否有效仍需实测。[S21]

### 10.3 报告只留下值得带走的东西

默认报告建议收敛为：本次任务与结果、三张关键现场照片、两到三个实际追问、个人核心结论、能力自测与下一步阅读。详细事件、全部照片和扩展问答折叠为附录。

三张自动照片优先选：一次请求与反馈、上下文整理的前后关系、新会话读取经验。不是每到一站机械拍一张。照片带事件编号、说明与实际时间；没有现场采集就标缺失。

“已参观”“完成实验”“通过考核”分开记录。系统不得因用户停留过一站，就写成“已经掌握该原理”。报告只总结实际发生过的提问，不把系统推荐的问题写成用户问过。

### 10.4 证书与结业

保留实习纪念证明和向导师告别的仪式，但不让姓名填写、下载或考试成为离开的阻碍。未考核也可以拿到参观记录；通过考核再生成相应标识。

结尾不必再次讲全套名词。一个新情境、一段解释、清晰的学习地图，比长篇鼓励文案更有价值。

## 11. 技术实施：复用现有底座，只拆开关键耦合

### 11.1 三个状态必须分开

**任务状态：** 委托、可用证据、工具请求与结果、当前工作上下文、保存的资料、交付与授权。

**导览状态：** 当前章节、讲解段、追问面板、镜头、教学回放位置、暂停与回访。

**学习状态：** 实际看过的事件、完成的对照实验、提问、照片、答题、复习记录。

观察一个事件，不等于再执行一次事件；回放一个动作，不等于再写入一条长期记忆；结束讲解，不等于任务成功。

不需要先引入复杂状态管理框架。先用清楚的数据结构与事件规则把三者分开，测试核心不变量。

### 11.2 对现有文件的改造建议

| 文件/模块 | 保留 | 建议改造 |
|---|---|---|
| `content.mjs` | 文案、问题、题库集中维护 | 按学习目标与观察章节组织；问题绑定场景条件与依据 |
| `engine.mjs` | 确定性教学、事件日志、幂等思想 | 从库存礼盒改为证据与简报；执行由任务事件驱动，不由进入站点驱动 |
| `scene.mjs` | 场景、导师、观察位、设备建模底座 | 建筑中性化；资料卡有稳定身份；聚焦与运行分离；局部遮挡处理 |
| `app.mjs` | 页面交互入口 | 协调导览，不直接把镜头或面板操作当业务完成 |
| `store.mjs` | 本机持久化方向 | 保存 schemaVersion 与 scenarioVersion；旧礼盒记录只读归档或显式迁移 |
| `report.mjs` | 导出与截图关联 | 用学习证据生成摘要；保留首次/最佳成绩与来源版本 |
| `editorial/factory-blueprint.md` | 产品约定集中管理 | 更新主题、主线、比较基线、删减清单和真实性规则 |

以上文件在公开结构中存在；表内是建议职责，不表示所有建议已经实现。[S02、S04–S06、S26]

### 11.3 一份事件，驱动三种表达

同一事件记录至少能说明：发生了什么、输入是什么、结果是什么、产生了哪份证据、关联哪个教学目标。

场景据此决定哪台设备运行；导师据此决定现在能说什么；报告据此决定哪些内容可写入。不要三处各自编造一套“当前进度”。

业务结果已提交后，摄像机尚未到达，也可以等待观察；摄像机到达了但结果未产生，则应显示等待。这样时序才不会因为动画而被颠倒。

### 11.4 版本与事实清单

为课程结论维护轻量记录：`claimId`、通用/实现/模拟类型、上游版本与来源、审核日期、对应文案、对照实验和考核目标。

比例、工具名、默认参数等变动性较高的内容优先进入此清单。发布检查应能发现：没有来源的 Hermes 实现声明、没有主线教学覆盖的核心考题、没有可观察结果的交互。

不要先造一套大型课程编译平台。用 JSON 或现有模块维护，足以支撑第一轮改造。

## 12. 改造优先级：先删负担，再补闭环，最后扩展

| 优先级 | 工作 | 明确验收产物 | 暂时不做 |
|---|---|---|---|
| P0-A | 固定新委托与证据材料 | 两条正确简报、重复与夸大问题、真实可追踪的依据 | 多行业、多任务大厅 |
| P0-B | 重写五章主线及新会话尾声 | 不点追问仍能讲清基础机制与 Hermes 复用 | 大量新设备与角色 |
| P0-C | 拆开任务、导览和学习状态 | 回访/回放不修改业务；保存与读取有事件证据 | 复杂工作流平台 |
| P0-D | 同步技术事实与比较基线 | 不把模拟当实测，不把可选机制说成必经工序 | 模糊的“唯一、自进化”宣传 |
| P1-A | 统一追问与核心界面 | 主线可连续推进；问题返回原位；操作不丢状态 | 多套身份模式与层层弹窗 |
| P1-B | 聚焦、稳定镜头与无障碍 | 遮挡可控，运行可信，减少动态与键盘流程完整 | 更多粒子、常驻环绕、写实建模 |
| P1-C | 报告和情境考核 | 实际观察生成报告；首次与复习成绩分开 | 排行榜、徽章经济、强制分享 |
| P2 | 深入实现、受控运行观察、真实轨迹回放 | 每项明确模型/工具/数据范围与版本 | 默认接入实时模型、自由自治多 Agent |

推荐先做一条完整纵向切片，而不是按文件并行铺开所有新功能。切片通过理解测试后，再把相同规则扩展到全部内容。

## 13. 验证计划：测“是否学会”，而不是只看“是否喜欢”

### 13.1 首轮形成性测试

建议邀请两组各约 5–6 人：经常使用 AI 但不了解 Agent 架构的访客；有软件经验但未系统了解 Hermes 的程序员。该规模用于找明显问题，不足以证明统计显著优劣。

让参与者在不被讲解员提示答案的情况下完成主线；记录停顿、误操作、错误解释与不必要的追问。对照当前版本时尽量平衡经验差异，报告原始人数与观察，不编造精确提升百分比。

体验结束立即做迁移题；经参与者同意，再于之后用不同表述的题检查保持情况。不要只问“满意吗”和“是否觉得更懂了”。

### 13.2 建议观察的指标

| 目标 | 观察指标 | 起始验收目标（非实测结果） |
|---|---|---|
| 轻松进入 | 是否知道能得到什么、是否需要解释入场操作 | 大多数人无需口头帮助即可启动 |
| 因果理解 | 能否解释一次工具返回为什么改变后续动作 | 关键误解逐个消除，而非只追求平均分 |
| Hermes 差异 | 能否指出新会话里保存、读取、复用的证据 | 不把它解释为自动训练了模型 |
| 可选深入 | 不追问能完成；追问能返回；开发者能找到依据 | 核心路径与深入路径均无死路 |
| 视觉清晰 | 能否迅速指出焦点、运行者及结果去向 | 无持续遮挡、无“所有设备都在工作”的误读 |
| 舒适可控 | 手动操作、暂停和减少动态是否有效 | 动画不抢回控制权，暂停不自行恢复 |
| 学习成果 | 首次题、迁移题、复习后的变化 | 分开记录，不用最高分掩盖首次误解 |
| 运行稳定 | WebGL、恢复、导出、移动端与弱设备表现 | 不损坏状态；降级路径可完成课程 |

帧率、加载体积、输入响应等应在指定设备、网络与画质下设预算并实测。报告不预设“用了某个像素比就一定流畅”。

### 13.3 自动化回归重点

回访不重复执行；追问不推进任务；拒绝保存不会产生长期条目；新会话不偷带完整旧上下文；已有资料未读入不能假装已用；当前要求不会被旧偏好覆盖；压缩后档案仍可按约定回查；失败动作不能生成成功交付；未授权不外发；截图失败如实记录；导出不包含不存在的提问；旧记录升级不丢失；键盘和文字模式能完成核心学习。

测试数据仍在本机。现项目没有远程学习分析，若未来添加遥测，应单独征得同意；不要把隐私边界作为产品优化的隐形代价。[S02]

## 14. 主要风险与取舍

**简化过头：** 把所有机制藏到追问，会留下一个好看但没有知识骨架的故事。应先确定核心学习合同，再决定能删什么。

**隐喻过度：** 给抽象概念配太多实体岗位，容易把程序调度讲成公司管理。工厂只负责空间关系，机制仍使用真实名称与输入输出。

**为了差异化而夸大：** 不应把其他 Agent 描绘成完全没有记忆。比较配置与集成取舍，而不是比较被弱化的对手。

**模拟过分顺利：** 一路绿灯让人误以为框架会保证事实正确。至少保留一次事实纠正和一次摘要丢失的可选对照，并说明检查能力的范围。

**自由探索挤占学习：** 保留它，但让默认导览免除移动操作负担。现场问答与观察优先于寻路和收集。

**把完整变成冗长：** 报告、考核、证书和告别都保留，但每一步只有一个主要动作，允许保存后离开和稍后继续。

**版本维护成本：** 把稳定原理留主线、变化参数留实现面板；依靠事实清单与固定来源减少连锁改稿。

## 15. 最终建议

这座工厂不需要变得更大，而需要变得更有因果。

主线只回答两个问题：

**第一，这一次任务是怎样完成的？**  
**第二，下一次任务为什么可以不完全从零开始，又为什么不能照搬过去？**

第一个问题让人理解 Agent；第二个问题让人理解 Hermes 的长期资料、技能复用与持续工作取向。其余技术细节，都应附着在这两个问题上，而不是让游客为了名词绕遍整座工厂。

最终应达到的效果是：普通人不必学操作游戏，也能看懂；程序员不必另走一套课程，也能深入；不追问的人带走完整骨架，追问的人得到真实机制和边界；所有人离开时都有可解释、可检验的学习成果。

**验收时最有价值的一句话，不是“这个工厂做得很炫”，而是“我现在知道它为什么要这样工作，也知道它哪里仍然会出错”。**

# 附录 A：可直接使用的主线编辑合同

| 章节 | 进入前状态 | 必须呈现 | 退出后状态 | 默认追问 |
|---|---|---|---|---|
| 接到委托 | 不完整资料、只授权草稿 | 模型请求与工具执行分离 | 有待执行的查证动作 | 为什么不直接写？谁真正去查？ |
| 查证回路 | 来源未核对 | 获取原文、合并重复、纠正夸大 | 有依据的工作结论 | 工具也会错吗？固定流程能做吗？ |
| 有限工作台 | 工具结果和历史开始积累 | 当前输入与档案分开；可选长过程压缩回放 | 可解释的精简输入 | 少带资料会忘吗？原文还在吗？ |
| 交付与沉淀 | 结论有证据、无外发授权 | 结果验收；保存哪些资料的明确决定 | 草稿已完成；长期条目有写入证据或明确未保存 | 怎么判断完成？这算训练吗？ |
| 新会话复用 | 新要求、旧会话不再整段可见 | 读取记忆、按需读 Skill、检索旧记录、重新核实 | 能解释复用与当前判断的边界 | 为什么仍要查证？别的 Agent 没有吗？ |

每章至少包含一个因果变化，不以“读完三段话”作为唯一完成条件。用户可以跳过动画，但应能看到等价的前后状态和解释。

# 附录 B：扩展问答的优先清单

| 问题 | 回答必须覆盖 | 适合的演示 |
|---|---|---|
| 模型和 Agent 是同一个东西吗？ | 模型产出请求/回复；运行时提供循环、工具与状态 | 请求卡停在执行前 |
| 工具成功为什么任务还可能失败？ | 局部成功不等于整体满足委托 | 成功读取了错误版本公告 |
| Skill 和 Tool 有什么不同？ | 方法说明与执行能力不同；读手册不等于已操作 | 手册打开后仍需发出调用 |
| 上下文与历史有什么不同？ | 当前输入与持久记录不同 | 档案很多、工作台只选部分 |
| 记忆与 Skill 有什么不同？ | 持久事实/偏好与可复用方法不同 | 同一新任务分别读取两类资料 |
| 为什么压缩有风险？ | 摘要可能遗漏条件、状态和来源 | “申请试用”被丢掉的对照 |
| Head/Tail 为什么保留？ | 当前策略保护起始约束及近期交接，非永恒不变 | 尾部滚动与完整工具对 |
| 为什么不是到 100% 再整理？ | 后续结果、输出和估算余量；阈值依配置 | 同一教学负载下的预算变化 |
| FTS5 与向量检索有什么区别？ | 词法匹配与语义相似检索分工 | 术语命中与改写可能漏召回 |
| WAL 解决什么？ | 数据库读写与恢复，不是 Agent 调度 | 作为档案室内部机制展开 |
| “越用越好”是不是训练权重？ | 资料与技能更新不同于训练；不保证无条件改进 | 保存文件而不是大脑升级 |
| 真实 Hermes 会完全按这条路线走吗？ | 教学观察路径与真实执行路径不同 | 展示可跳过/循环的轨迹 |

# 附录 C：发布前核对清单

1. 主线五章都能用一句白话问题概括，且没有靠追问补前置知识。
2. 进入任何观察位都不会直接重复业务副作用。
3. 两次任务存在明确的新会话边界，且没有偷偷带入完整旧上下文。
4. 所有被声称已使用的记忆/技能，都能定位到读取证据。
5. 比较对象写明是最小配置，不代表所有常规 Agent。
6. 不是每次任务都强制压缩、调用所有工具或进入训练区。
7. 缩比参数、虚构教材、预编问答、真实观察的标识清楚。
8. 所有核心技术声明都有来源类型和适用版本。
9. 运行高亮与讲解焦点独立；背景没有无意义运动。
10. 追问、退出、回放、暂停与恢复不会丢失状态或改变证据。
11. 相机在阅读时稳定，减少动态模式与键盘路径完整。
12. 截图来自真实渲染帧，失败不造图，报告不造提问或掌握记录。
13. 考核包含新情境，不只考缩写和场景记忆。
14. 旧版参观记录有保留方案，升级不会静默覆盖。
15. 不把未做的设备、性能和可用性测试写成已通过。
